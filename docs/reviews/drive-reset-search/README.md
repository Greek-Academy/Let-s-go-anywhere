# 保存データ削除後に所要時間が表示されない問題

2026-10-21 / Issue #126 / PR #125。

## 原因

「モックの保存データを削除」で保存状態と現在地は初期化されますが、検索画面のメモリーには候補と「起動時の検索は実行済み」という印が残っていました。現在地を破棄すると所要時間も破棄されるため、古いパネルだけが「未確認」で表示され、初期設定をやり直しても再検索されませんでした。

修正前の無料テストで、削除・再設定後に2回目の検索が始まるべきところ、1回のままであることを再現しました。

## 修正

初期設定前の状態へ戻ったら、検索の候補・エラー・利用状態・起動時の実行済みフラグも初期化します。待機中・通信中の画面側の処理は中止し、遅れて届く削除前の結果を表示しません。

初期設定を終えた後は現在地と新しく選んだ趣味で一度検索し、取得できた所要時間を表示します。キャンセル時は元の候補と時間を保ちます。Googleが経路を取得できない候補、位置の利用終了・時間の期限切れでは従来どおり「未確認」を表示し、時間を推測で埋めません。

APIキー、サーバー上の利用記録、写真、Googleの設定は変更しません。新しいホーム検索には従来どおりAI・経路計算の料金が発生します。削除操作で送信済みの検索を取り消したり返金することはできません。

## 確認する操作

このMacの `http://127.0.0.1:5211/#/` を一度再読み込みすれば、今回の修正を読み込めます。保存データを消し直す必要はありません。

削除後の流れを試す場合は、設定の「モックの保存データを削除」→「削除して最初から始める」→趣味を選択→「ドライブ先を見つける」。現在地を許可して待つと新しい候補と取得できた時間が表示されます。削除操作では「行きたい」などの端末内データが失われるため、通常の表示確認は再読み込みだけで行えます。

## 検証

- 修正前：削除後に新しい検索が始まらないテスト2件が期待どおり失敗。
- 修正後：検索連携81件成功（PC・スマホChromium・スマホWebKit）。削除後の新しい趣味・現在地・所要時間、キャンセルでの維持、削除中の遅延応答を確認。
- 公開検索のログイン・待機・ログアウト・アカウント分離12件成功。
- 型チェック・ビルド・整形・入力確認ツールのビルド・静的配信物検査成功。
- 検証は独立した作業場所の無料サンプルとFirebaseエミュレーターを使用し、実API接続画面の編集による繰り返しの自動再読み込みを避けました。実機と公開Webへの反映は今回の対象外です。
