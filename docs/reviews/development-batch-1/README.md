対象は #44、#42、#20 の、施設契約や本番APIの決定を待たずに実装できる画面・判定処理です。各Issueの本番完了条件は残っています。既存の #4／PR #47 を土台にしており、自動マージやIssueのクローズは行いません。

## #44 最後の500mの下見カード

[確認画面](http://localhost:5173/#/events/fuji/arrival) ／ [画像](arrival.png)

- 詳細の「最後の500mを、見ておこう。」から開く。車入口、歩行者入口、駐車条件、4段階の入出庫、代替候補、項目ごとの確認元・日付を確認できます。
- 車入口が未確認の場合は入口図や車入口の地図ボタンを出しません。`fireworks` は未確認、`forest` は期限切れのサンプルです。
- 期限切れ・掲載停止・情報不足は以前の値を表示しません。写真なし・読込失敗・許諾無効時は文章の案内を残します。地図ボタンは外部案内のデモです。
- 戻ると元の詳細と「行きたい」タブが維持されます。保存済みの候補も最新の根拠・期限を使います。

人間側に残ること：#43 の施設選定・現地／施設確認・写真許諾・内容承認。入力項目は [確認ひな形](../../ARRIVAL_CONTENT_TEMPLATE.md) に記載しました。

開発側に残ること：管理画面、実施設データの公開・訂正・停止、キャッシュ更新、確認済み車入口の実リンク。写真は実施設のものをまだ収録していません。

## #42 今回のお出かけ条件（一人利用）

[ホーム](http://localhost:5173/#/discover) ／ [入力](conditions-input.png) ／ [結果](conditions-results.png) ／ [理由](conditions-reasons.png)

1. 出発エリアを「東京・渋谷駅周辺」にする。
2. 「今回のお出かけ条件」で、2026-09-19、09:00出発、18:00帰宅、8,000円、夜間を避けたい、と入力して保存する。
3. 「確認済みで合う」はカフェ1件、「合わない」は花火1件、「未確認」は4件。理由から時間・費用範囲・経路条件と根拠を確認できる。
4. 出発エリア、日付、時刻がサンプルの確認条件と異なると未確認になる。条件の解除と再設定ができる。
5. お出かけ詳細の「このお出かけの条件」はその候補だけに保存され、ホームの検索条件・別候補・趣味・知識チェックを変えない。

数値や確認元は架空のサンプルです。確認期限2026-12-31を過ぎると未確認になります。空欄や部分費用、予算幅の一部だけが収まるケースも適合に含めません。避けたい場面を満たさない条件を投票や興味によって解除する処理はありません。

人間側に残ること：#41 の公開用の条件・費用範囲・根拠・共同利用時の共有ルールの承認。

開発側に残ること：API・アカウント同期、複数人の費用配分・共有条件・運転者の権限、保存した旅行単位での余白等の拡張。現在は日帰りの画面を先行実装しており、実経路・交通状況を確認するサービスではありません。

## #20 SNSリンク保存の入力・重複処理

[行きたい](http://localhost:5173/#/saved) ／ [重複案内](sns-duplicate.png)

1. `https://twitter.com/sample/status/12345?s=20` を追加する。
2. `https://x.com/sample/status/12345/photo/1?t=tracking` を追加すると同じ投稿として案内され、保存済み一覧に戻れる。
3. 不正なURLを入力してもタイトル・入力を消さずに訂正できる。未解決のTikTok短縮URLも「内容未確認」の個人リンクとして残る。

HTTP(S)以外、認証情報、IPアドレス・ローカルホスト・通常外のポート・制御文字等を拒否します。媒体名はドメインの境界を確認して識別します。一般サイトのクエリやフラグメントは勝手に削除しません。入力時の元URLも保持します。

人間側に残ること：#7 の公開への利用条件とレビュー対象の決定。

開発側に残ること：本人専用のAPI保存、短縮URL解決・DNS／リダイレクト検査・タイムアウト等のサーバー対策、運営レビューとの紐付け。今回のブラウザ内検証をサーバーのSSRF対策の代用にはしません。
