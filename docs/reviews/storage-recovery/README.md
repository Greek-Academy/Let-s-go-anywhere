# Issue #31：端末内データの検証と復旧

確認日：2026-09-16。PR #61を確認後にmainへ反映し、そのmainから次の開発として実装しました。今回の中心は現行モックの保存データで、本番の認証・会社間の権限検証とは区別します。

## 変更前に再現した問題

- 保存されている相談メモが`null`の状態で知識チェックを開くと、`goal`を読み取れずアプリの画面が消えました。
- 不正なJSONを再読み込みすると、初期データで自動的に上書きされ、元データが残りませんでした。

今回、保存データを項目ごとに検証し、読める領域だけで画面を開くように変更しました。読み込みに問題がある場合は自動保存を止め、元データを残します。新しい確認画面で初期化を確定するまで、破損した元データも自動で削除しません。

## 操作と確認画面

通常の画面は引き続き利用できます。プロフィール → 設定に「端末内の保存」を追加しました。問題があるときは画面上部からも設定へ進めます。

| 画面 | 確認内容 |
| --- | --- |
| [PC：保存状態と復旧案内](desktop-recovery.png) | スマホ枠・内部スクロール・設定からの対処 |
| [WebKit：元データの保持とダウンロード](webkit-recovery.png) | 読めない領域があること、未保存の変更との区別 |
| [320px：初期化の確認](webkit-reset.png) | キャンセルで保持、確定時のみ削除。通知もモーダルの背景になる |
| [320px：読み取れた保存候補](webkit-retained.png) | 他の領域に不正値があっても、有効な保存候補を見られる |

保存容量不足などの書き込みエラーでは「保存をもう一度試す」を表示します。不正な元データや別タブの変更があるときは、このボタンで強制上書きさせず、ダウンロード・読み直し・確認付き初期化を案内します。

画面確認中に見つけた、直接入力したハッシュURL間で別画面のスクロール位置を引き継ぐ問題も修正しました。ルートのパスと検索条件を履歴キーに含め、再現テストを追加しています（#32の画面移動の補修）。

## 確認方法

この変更のローカルプレビューは `http://127.0.0.1:4189/`（開発PCでサーバー起動中のみ）。通常の起動は `npm ci` → `npm run dev`、表示されたURLへアクセスします。

普段のブラウザに不正データを入れる必要はありません。以下のテストは、普段の保存領域とは別のPlaywrightブラウザで架空データを使って失敗・復旧を操作します。

```bash
npx playwright install chromium webkit
npm run build
CI=true PLAYWRIGHT_PORT=5193 npm run test:preview -- tests/storage.spec.ts tests/storage-flows.spec.ts
npm run test:report
```

画像の再生成も別のブラウザを使います。プレビューを起動した状態で `CAPTURE_BASE_URL=http://127.0.0.1:4189 node scripts/capture-storage-recovery.mjs` を実行します。

- 不正なJSON・配列・型・未知の項目・プロトタイプ用のキー・不完全な同意記録は、画面用の正しい状態として使わないことを確認。
- 保存URLとマークアップが勝手に実行・取得・おすすめ掲載されないことを確認。
- 元データのダウンロード内容が保存文字列と一致し、キャンセル・削除失敗時にも元データが残ることを確認。
- 読み込みだけでは正しい保存も書き直さず、別タブの不要な競合を作らないことを確認。
- 既定の本人用バックアップ名を配信物検査で拒否。
