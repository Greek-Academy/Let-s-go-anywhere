# Issue #90：共有「行きたい」の端末内デモ

2026-10-03。PR #89（講習紹介の終了・4タブ化）を土台にした追加です。[操作ガイド](../../SHARED_WISHLIST_DEMO.md) / [人間の準備 #91](../../SHARED_WISHLIST_FIREBASE_SETUP.md) / [設計](../../SHARED_WISHLIST_DESIGN.md)。

## できるようになったこと

個人の「行きたい」を維持したまま、名前付きのリストを作り、招待・参加承認・候補の持ち寄り・それぞれの反応を試せます。共有メモ、未回答／両者が興味ありの絞り込み、退出・削除・作成者の引き継ぎもデモ内で操作できます。

**別端末共有は未実装です。** 画面の「あなた／はる」は同じ端末の操作役です。外部に招待や候補を送信していません。親 #40 は閉じず、認証・権限ルール・Firestore保存・HTTPS招待・2アカウント実共有を残しています。

## ユーザーが試す3操作

1. 行きたい → 私の行きたいの切り替え → 新しいリストを作る。
2. リスト右上の歯車 → デモの招待を作る → 相手役の参加申請 → 作成者として承認。
3. 候補を追加し、操作役を切り替えて「行きたい」「気になる」を選ぶ。「二人とも興味あり」で候補が残ることを確認。

## 今回確認したこと

| 検証 | 結果 |
| --- | --- |
| 整形・TypeScript・通常ビルド・iOS同期 | 成功 |
| 共有機能の操作・保存ルール | 新規15ケース×3プロジェクト＝45件成功。PC、スマホ幅Chromium、スマホ幅WebKit |
| 関連する既存機能 | 旧保存の破損・容量不足・更新競合・リセット、講習終了後の4タブと学習の検証も含む計72件成功 |
| iPhone 17 / iOS 26.5 Simulator | XCTest 1件成功。実際のWKWebView・Preferencesで作成、申請、承認、再起動後の保存を確認 |
| 横幅・見た目 | 402pxの候補／設定に横はみ出しなし。320pxの操作・ダイアログも確認。下部4タブ、既存の白・ティール・写真カードを維持 |
| 外部通信・秘密情報 | 共有フローで新しい外部リクエストなし。変換の許可項目を検査し、個人メモ・検索希望の理由が共有JSONに入らないことを確認 |

実機iPhone・本物の別アカウント・サーバー側のアクセス制限を検証した結果ではありません。詳細なCI結果はPRのChecksを参照してください。

失敗系では、承認前・退出後の操作拒否、招待の期限切れ／失効、反応の独立、重複追加、作成数・候補数上限、破損データの維持、容量不足、別画面で更新中の入力保護と上書き停止を検査しました。個人保存の全削除に共有デモの削除も含まれることを確認しています。

初回のiOSテストは、ボタン内の文章を独立したテキストとして探すテスト側の指定で失敗しました。アクセシビリティ階層にある実際のボタンのラベルで照合し直し、アプリの変更なしで作成から再起動まで成功しました。

## 保存・費用への影響

共有デモは新しいキー `driveplus.sharing.demo.v1` に保存し、個人の `driveplus.mock.v1` は移行しません。リセットは両方のキーを削除します。保存窓口を分けていますが、デモJSONをそのままクラウドに上げる実装ではありません。

追加料金0円。外部API・課金設定・デプロイなし。既存のWeb実検索の回数を消費していません。出典を開く明示操作は従来の外部リンク確認へ進みます。
