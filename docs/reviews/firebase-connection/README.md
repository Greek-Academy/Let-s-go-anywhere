# Firebaseログイン・本人用リストの接続確認

Issue #93。以下の画像は**ローカルのFirebase Emulator**と架空のメール `demo-owner@example.test` で取得しました。実クラウド・実メール・実機での共有成功を示す画像ではありません。

1. [ログイン](01-login.png)：共有用アカウントの登録・ログイン。個人の保存を自動送信しない説明。
2. [保存前の確認](02-save-preview.png)：リストの名前と色を選択し、保存先を確認。
3. [保存結果](03-cloud-list.png)：本人のみのリストを保存し、読み直し・編集・削除できる。

確認した結果：

- 権限テスト8件：本人CRUD、未確認・未ログイン・他人拒否、3件上限、スキーマ/個人フィールド拒否、サーバー時刻、改訂番号。
- Firebase画面21件：PC/スマホ幅Chromium/スマホ幅WebKit。確認メールの消費、同一アカウントでの再ログイン、別アカウント分離、競合での入力保持、再設定、320px、通信断、バックグラウンド、端末内リセット。
- 既存共有・設定境界51件、掲載情報入力ツール51件。通常版はFirebaseへ接続しない。
- 型チェック、通常版/接続検証版/掲載確認版のビルド、通常プレビュー配信物検査。
- `npm audit --omit=dev`：0件。FirestoreのNode向けgRPC依存に修正版を適用してEmulatorで再検証。

最初のブラウザ試行は入力欄・statusのテスト用識別と、ハッシュ移動を再読み込みと誤って仮定したテストで失敗しました。入力欄のアクセシブル名とテストを修正し、21件をまとめて再実行して成功しました。通常版の初回検査は既存の5187番サーバーと衝突したため、未使用5196番で再実行して成功しました。

開発用Firebase CLIの推移依存にnpm auditの指摘（11件）が残ります。アプリ配信には含まれず、CLIではEmulator・ログイン・Firestore Rules反映に限定します。CLI更新時に再評価し、互換性の異なる一括ダウングレードは行っていません。一般公開の準備完了とは扱いません。

未確認：検証プロジェクトへの権限ルール適用、ユーザーの実メール確認、実iPhoneでの往復。相手の招待・候補・反応は後続 #94。操作・反映手順は [接続検証のガイド](../../FIREBASE_CONNECTION_PILOT.md) を参照してください。
