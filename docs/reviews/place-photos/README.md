# 3店舗限定・実写真の取得検証（#118）

対象は京都のイノダコーヒ本店、スマート珈琲店（寺町）、小川珈琲堺町錦店です。店舗公式の住所を使い、Google側の店名・市区町名・番地が一意に一致したときだけ1枚取得します。対象外と取得失敗はイラストです。

## 2026-10-18の実検証結果

Macの検証画面で取得ボタンを操作し、3店舗とも画像が読み込まれました。Google側の店名・住所は固定データと一意に一致しています。各カードのGoogle Maps表示、撮影者1件、元写真へのリンク1件も確認しました。

[Google公式料金表](https://developers.google.com/maps/billing-and-pricing/pricing)の無料枠を適用しない掲載単価では、`3 × $0.032 + 3 × $0.007 = $0.117`（税・為替など別）です。無料枠が残っていればその範囲ですが、請求先の他の使用量を含む実請求は未確認です。Google Cloud側で確認してください。

## 写真を確認する操作

実取得に使った確認用ブラウザのタブをMacで開いたままにしています。そのタブをスクロールして3店舗の写真を確認します。表示はメモリ内だけなので、画面を閉じたり再読み込みしたりすると消えます。下記URLを新しく開いても写真を再取得せず、イラストと実行済み表示になります。

http://127.0.0.1:5186/#/photo-pilot

## 初回の取得手順（実行済み）

1. [キーの作成・保存手順](../../PLACE_PHOTOS_PILOT.md)に沿って準備する。

## 開発側の検証

- サーバー6ケース：対象外・キーなしではGoogleへ送信しない。同時操作・再起動で上限をリセットしない。名前一致だけ・番地の部分一致・複数候補は写真取得へ進まない。API例外・不正URL・過大応答でも秘密を返さず自動再試行しない。
- PC Chromium／スマホWebKitの6フロー：取得ボタン・撮影者・元写真リンク・画像失敗時のイラスト・再読込時の取得停止を確認。レスポンスを架空データに差し替え、外部APIは呼んでいません。
- 開発サーバーでも.envを配信せず、外部Origin・トークンなし・対象外IDを拒否することを確認。
- 写真データはカード表示の間だけ。ブラウザ保存・共有・キーの配信なし。
- 前回のCIでは、既存の掲載情報ツールがアプリを表示する際に`__PLACE_PHOTO_PILOT__`が未定義となり、18テストが失敗しました。専用ビルド設定で写真検証を明示的に無効化して修正しました。既存の54ケースを確認し、実データの取り込みや外部APIの接続なしで通過しています。
- 通常アプリと掲載情報ツールの配信ファイルに、写真検証画面・取得API・未定義のフラグが残らないことを確認しています。
- CIに実キー用の.envファイルがない場合、ViteはそのURLにアプリのHTMLを返します。写真用テストが「実キーのファイルが存在する」前提だったため失敗していた点も修正しました。専用の架空.envファイルでHTTPアクセス拒否と内容の非公開を確認し、テスト後に削除します。実キーのファイルは変更しません。

## 2026-10-19のキー制限確認

ユーザーの設定画面で、選択中のAPIがPlaces API (New)の1件だけになっていることを確認しました。その後、ユーザーから保存完了とPRのマージ承認を受けています。制限後に実APIを再実行して確認したものではありません。取得枠は使用済みのまま維持します。

## 人間側で残る確認

- 開いた画面で写真の内容を見て、店舗に合っているか・パネルの見え方がよいか確認する。
- Google Cloudの使用量・請求を確認する。こちらで確認したのは成功したAPIの呼び出し回数で、Googleの請求管理画面は未確認。

公開URLとiPhoneアプリは今のイラスト表示を維持します。今回のルート・取得APIは専用の開発モードだけで有効です。一般公開版へ写真を接続するのは、実写真・費用の確認後です。
