# Issue #32：画面移動・キーボード操作とWebKit検証

確認日：2026-09-16。施設・写真の選定を待たずに進められる、サンプルアプリの操作改善です。実機・本番APIを含むIssue全体の完了ではありません。

## 変わった操作

- 初回設定、5タブ、詳細などへ移動すると、その画面の見出しへフォーカスを移します。入力欄には自動フォーカスしません。ブラウザのタイトルも画面に合わせます。
- 詳細からアプリの「戻る」、またはブラウザの「戻る・進む」を使うと、元のカード／メニューとスクロール位置へ戻ります。対象が保存解除などで消えた場合は見出しへ戻します。
- 同じ画面内の条件チップ・保存一覧の切り替えでは、押した操作からフォーカスを移しません。地図／一覧の表示切り替えでは各表示の見出しを使います。
- WebKitでボタンをクリック／タップしてシートを開いた場合も、閉じると開いたボタンへ戻します。シート内はTab／Shift+Tabでリンクも含めて巡回し、Escapeで閉じられます。
- 写真カードのキーボードフォーカス枠を内側に表示し、角丸カードに切り取られないようにしました。通常時の色・寸法・写真配置は維持しています。

移動履歴はブラウザのタブ内メモリで最大100エントリーだけ保持します。保存するのはスクロール位置と操作識別子で、入力値・DOM本文は保存しません。リロードでこの移動履歴はリセットされます。既存のプロフィール・保存・相談メモ等のlocalStorageとは別のものです。復帰する操作の識別子がない画面でも、見出しへ戻って続けられます。

## 手元で試す

```bash
npm ci
npx playwright install chromium webkit
npm run dev
```

通常のURLは `http://localhost:5173/`。このPRの作業用プレビューは `http://127.0.0.1:4188/`（開発PCでサーバー起動中のみ）です。

1. 「見つける」で下のカードまで移動し、Tabキーで写真に枠を出してEnterで詳細を開く。
2. 「戻る」をキーボードで押す。元のカードの枠とスクロール位置が復元される。ブラウザの戻る／進むでも確認できる。
3. 各下部タブ、右上プロフィール、プロフィール編集をキーボードで開く。新しい画面の見出しから続けられる。
4. 「行きたい」のお出かけ／車候補を切り替え、選んだボタンにフォーカスが残ることを確認する。
5. お出かけの絞り込みを開く。Tab／Shift+Tabでシート内を移動し、Escapeで閉じ、開いたボタンに戻ることを確認する。
6. 保存URLの案内では、Tabで「元のページを開く」にも移れる。リンクを押すと実際に外部ページへ移動するため、確認用のURLを使う。

変更前には、Chromiumで画面見出しへのフォーカスがないこと、新規WebKit実行でシートの復帰・リンクのTab移動に失敗することを再現しました。日本語の外部404ページはテスト用HTMLにもUTF-8を明示し、画像テストは遅延画像が画面内に入るまでスクロールする操作へ修正しています。外部404はローカルで応答を置き換え、実サイトにはアクセスしません。

```bash
npm run format:check
npm run build
npm run build:review
npm run verify:preview
CI=true PLAYWRIGHT_PORT=5191 npm run test:preview
CI=true npm run test:review
```

WebKitだけなら `CI=true PLAYWRIGHT_PORT=5191 npm run test:preview -- --project=mobile-webkit`。CIのHTMLレポートにはプロジェクト名、成功画面、失敗時トレースを残します。
