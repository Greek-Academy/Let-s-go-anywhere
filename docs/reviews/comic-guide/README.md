# 漫画でわかるDrive+の使い方（Issue #143）

目的地を決められない利用者が「走りたい」から出発し、趣味・気分・自由な言葉から行き先を見つける流れを、承認済みの6ページの漫画で案内します。

## 利用者の体験

- 初回: 開始画面の「はじめる」→ 漫画ガイド → 実際の趣味設定 → 検索待ち → 結果の並ぶホーム。
- ホームの下部: 「行き先探しに、迷ったら。」の「このアプリの使い方」→ 同じ漫画を先頭から読む → 閉じる／ホームへ戻ると元の位置へ戻る。
- 設定済みの利用者は引き続きホームから開始。漫画を読むために初期化する必要はありません。

## 確認していただきたい3操作

1. 初回案内を `http://127.0.0.1:5211/#/welcome` で開き、「はじめる」。左右のスワイプ・次へ・前のページ・ドットから6ページを読みます。
2. 最後の「さっそく、趣味を選ぶ」で趣味設定へ。「戻る」で漫画の最終ページへ戻れ、選んだ趣味は残ります。「ドライブ先を見つける」以降は既存の検索動作です。
3. ホームを下までスクロールして「このアプリの使い方」を押す。右上の閉じる・最終ページの「ホームへ戻る」で見ていた位置に戻ります。

設定を変えずに漫画だけを見る場合は `http://127.0.0.1:5211/#/guide` を開けます。

## 設計・影響

承認された独立HTMLの漫画イラスト、セリフ、配色、6ページ構成をReactの画面へ移植しました。初回・再表示は同じデータとコンポーネントを参照します。左右キー・Home/Endキー、再表示時のEscapeにも対応。動きを減らす設定と文字拡大を反映し、小さい画面では本文を縦に読めます。イラストが読み込めなくてもセリフ・説明・操作を残します。

CSSはガイドとホームの案内部品に限定。画像はアプリ内の `public/images/guide/story-comic.png` に同梱し、外部画像サイトに依存しません。生成元と最終プロンプトは [ARTWORK.md](ARTWORK.md) に記録。元のHTML成果物は変更していません。

新しい保存項目やデータ移行はありません。趣味・保存済み候補・検索入力を維持します。漫画の閲覧・ページ移動・ホームからの再表示だけでは位置取得や検索を開始しません。趣味設定完了後とホームの検索操作は従来どおりで、実APIに接続した環境では従来のAPI費用が発生します。確認作業には無料の架空サンプルと通信の差し替えを使用しました。

## 検証

整形、型チェック・ビルド、入力ツールのビルド、静的配信物の検査を通過。入力ツールの54ケース、初回検索・保存リセット・バックグラウンド復帰の48ケースを通過しました。全体のブラウザ検査結果は完了後に追記します。

新しい回帰検査では、初回6ページ、趣味への往復、設定済み利用者の保存データ、ホーム位置とフォーカス復帰、文字拡大・小画面・画像欠落を確認。検索連携の検査で、漫画を再表示してもPOSTが1回のままで、10枚の候補が残ることを確認しています。Chromiumのタッチ入力による実際の横スワイプも確認済みです。
