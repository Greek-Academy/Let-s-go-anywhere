# タブ切り替えで現在地の検索が止まる問題

2026-10-25 / Issue #126 / PR #125。

## 問題と変更後の動作

検索中にブラウザが画面を非表示と判定すると、現在地を即座に破棄し、結果の受け取りも中断していました。「モックの保存データを削除」後に新しいタブで初期設定した場合も、この非表示イベントで「現在地の利用を終了しました」となります。

「見つける」では、一時的なタブ・アプリ切り替えで、進行中の検索、検索の順番待ち、表示済みの候補と所要時間を維持します。復帰による位置の再取得や検索の再送は行いません。

現在地は取得時刻から10分間だけメモリに保持します。切り替えで期限を延長せず、画面へ戻ったときにも実時刻で期限を確認します。バックグラウンドでタイマーが止まっていた場合も、期限切れの現在地を使い続けません。期限切れ・ページ離脱・再読み込み・アプリ終了・データ削除・ログアウト時の破棄を維持します。

位置を永続保存・共有したり、移動を追跡したりする変更はありません。「車を探す」と共有リストの背景移行時の処理は変更しません。現在地の説明文は保持時間と今回の動作に合わせて更新しました。

## 確認する操作

1. このMacの `http://127.0.0.1:5211/#/` を一度再読み込みし、現在地からの検索を開始します。保存データを消し直す必要はありません。
2. 検索中に別のブラウザタブへ切り替え、しばらくして元のタブへ戻ります。
3. 位置を取得してから10分以内なら、「現在地の利用を終了しました」で止まらず、候補と取得できた所要時間を確認できます。復帰で検索を追加しません。

再読み込み・新しいタブでの起動は新しい検索になるため、従来どおりAPI料金が発生します。一時的な切り替えは同じ検索の継続です。APIキーや課金設定の変更はありません。通信失敗・検索自体のタイムアウト・OSによるアプリ終了からの自動再送は行いません。Googleが時間を返せない候補は引き続き未確認です。

## 検証結果

- 修正前に、新しいタブでの検索中・順番待ち中の非表示を再現する2件が失敗することを確認。
- 修正後の検索連携96件成功。今回追加の15件で、保存データ削除後の新タブ、待機・通信中の非表示、結果と時間の維持、POSTが1回のままであること、10分後の復帰、ページ離脱と遅延応答の破棄を確認。
- ビルド済み画面の位置情報関連75件成功。「見つける」の期限延長がないこと、位置取得取消・拒否・再取得、別機能である「車を探す」の既存の位置破棄を確認。
- Firebase認証エミュレーターの公開検索12件成功。ログアウト・アカウント分離・順番待ちの中止を確認。
- 整形、型チェック、アプリと入力確認ツールのビルド、静的配信物検査成功。

PC・スマホ幅のChromiumとWebKitで、ブラウザの非表示・復帰イベントを明示的に発生させています。実Safariのタブ切り替えや実機iPhoneでのOS停止を直接検証したものではありません。APIキーを持たない独立した作業場所で無料サンプルを使用しました。今回の検証による実API呼び出しはありません。公開Web・インストール済みiPhone・mainへの反映は未実施です。
