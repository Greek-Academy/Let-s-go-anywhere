# 相手と「行きたい」を共有する

Issue #94 / 2026-10-04。端末内で役を切り替えるデモから、Firebaseにログインした別アカウント同士の共有へ進めました。

## まず試す3つの操作

検証用URL： **https://driveplus-fbc33.web.app/#/saved/cloud**

1. **あなた：** 前回作ったメールアカウントでログイン。「新しい共有リストを作る」で名前・色・相手に見せる表示名を入力します。「候補を追加する」で自分の保存から1件選ぶか、場所の名前と公開ページURLを入力し、共有前の確認画面から追加します。
2. **相手：** あなたが「メンバーを招待する」→「招待リンクを発行」→コピー／共有メニューで送ったリンクを、相手のiPhoneのSafariで開きます。相手自身のメールで登録・確認・ログインし、表示名を入れて「参加をリクエスト」を押します。あなたは「最新の内容に更新」→相手を確認して承認します。知らない表示名はLINE等で本人に確認してから承認してください。
3. **二人：** 相手が「招待の状態を更新」→「共有リストを開く」で候補を確認。「行きたい」「気になる」をそれぞれ選び、「最新の内容に更新」すると両者の反応が見えます。「二人とも興味あり」で共通の候補を絞れます。相手も候補を追加できます。

アプリのインストールは相手には不要です。Safariから試せます。すでにアプリにログインしていてもSafariとは別のログインです。メールアドレス・パスワード・確認メールのリンクを開発側へ渡す必要はありません。

人間にお願いするのは、**確認相手1人の用意と、この3操作の確認**です。招待リンクは相手にだけ送ってください。開発側から相手へは送信しません。

## 従来の保存との違い

- 「私の行きたい」は従来どおり、その端末／ブラウザの個人保存です。Safariを別のURLで開いても、MacやiPhoneアプリの個人保存が自動で移るわけではありません。
- 前回の本人用の準備リストは「以前の準備リスト」で確認できます。「新しい共有リストを作る」の際、名前・色を明示してコピーできます。元の準備リストは残します。
- 共有する候補を1件ずつ選び、共有画面を確認してから送ります。個人メモ・学習・不安・クイズ回答・現在地は自動で送りません。
- 共有するのはリスト名・色・参加者の表示名、選んだ候補のタイトル・地域・URL・出典状態・取得日時・共有メモ・各自の反応です。メールアドレスはほかの参加者に表示しません。Firebaseには認証・権限管理用のUIDと日時等も保存します。
- SNSリンクの本文や画像を自動取得する機能ではありません。サンプル／未確認の表示は共有後も残ります。候補の日時は情報を取り出した日時で、施設の最新情報の確認日ではありません。

## 招待とメンバー

- 作成枠は1人3リスト、参加者は1リスト5人、候補は100件まで。引き継いでも元の作成枠は使われ、リストを削除すると解放されます。
- 招待リンクは7日・1人分。リンクを開くだけでは候補を読めません。メール確認済みの人の参加申請を、作成者が承認します。期限はサーバーの時刻でも検査します。
- 取り消し・再発行すると古いリンク／未承認の申請を使えなくなります。参加者を追加する場合は新しいリンクを発行します。
- 反応は本人だけが変更できます。共有メモは候補を追加した本人が変更。作成者は候補を削除できますが、在籍中のほかの人のメモは書き換えません。
- 「メンバーと設定」で退出・メンバーを外す・作成者の引き継ぎ・リスト削除。引き継ぎは相手の受諾で確定します。
- 退出直後からサーバーは読み書きを拒否。候補・共有メモは残り、退出者の反応・投稿者表示・古い招待情報を整理します。退出前に相手が控えた内容まで回収する仕組みではありません。
- 整理／削除が途中で止まった場合、作成者がそのリストを開いて「処理を再開する」。処理中は共有操作を止め、全件が片付くまで完了扱いにしません。元の作成者UIDは作成枠管理のため、リスト削除まで保持します。

## 通信・ログイン・更新

共有データはFirebase Authentication＋Firestoreに保存します。独自の常時稼働サーバー、Functions、Storageは追加しません。HTTPSのアプリ配信はFirebase Hostingです。読み書きの許可は画面だけでなくFirestore Rulesで検査します。

ログインと取得キャッシュはメモリのみです。再読み込み・アプリ再起動時はログインし直します。バックグラウンド中は共有画面を隠し、戻ったら再取得します。端末リセットはクラウドのリストを削除しません。

候補と反応は「最新の内容に更新」で読み直します。メンバー変更・権限失効はリスト本体の変更通知も使って表示に反映します。チャットのような全候補の常時同期はしません。同じ候補の重複追加は1件にまとめ、古い画面のメモ編集は新しい編集を上書きせず、入力を残して再確認を案内します。通信エラー中は成功扱いにせず、古い一覧を消して再取得を案内します。オフライン編集の予約送信はありません。

## MacとXcode

```bash
npm ci
npm run dev:firebase
```

Mac専用URL：`http://localhost:5182/#/saved/cloud`。5173番の通常モックではFirebaseを無効にしており、実共有はできません。相手にlocalhostのURLを送らないでください。共有ボタンはHTTPSの招待リンクを作ります。

```bash
npm run ios:copy:firebase
npm run ios:open
```

XcodeでiPhone 17等を選び▶で実行。iPhoneアプリで受け取る場合は、共有一覧の「招待リンクから参加」にHTTPSリンクを貼れます。リンクからアプリが自動起動するUniversal Linksは後続です。`npm run ios:sync` は通常モックに戻すコマンドです。

## 費用・公開範囲・残ること

Sparkのまま、請求先との連携／Blazeへの変更はしません。独自ドメイン・Functions・Storage・OpenAI APIの追加呼び出しはありません。無料枠を超えた際の制限や広域運用の費用を、この小規模検証だけで判断しません。ConsoleのFirestoreとHostingで利用量を確認してください。

HTTPSで画面は配信しますが、候補データを静的ファイルに書き込んだり、ログインなしの公開リストにしたりしません。検索エンジン向けにnoindexも付けますが、URLの秘匿を権限管理の代用にはしません。

一般公開前には、アカウント全削除と復旧、App Check等の不正利用対策、プライバシー・利用条件の確認、費用・利用量の監視、実機での継続確認が必要です（#29・#31・#32・親#40）。通知、チャット、車候補の共有、Universal Links、個人保存の全端末同期は今回の範囲外です。

## 開発側の検査・反映

```bash
npm run test:firebase:rules
npm run test:firebase:ui
npm run format:check
npm run build
npm run verify:preview
npm run build:firebase
npx firebase deploy --only firestore:rules,hosting --project driveplus-fbc33
```

反映前にプロジェクトID・請求先連携なし・現行RulesとHostingの状態を確認し、現行Rulesをローカルへ退避。#93の本人用データを保持します。反映後にRulesの内容一致・HTTPSヘッダー・別アカウント間の往復と拒否を確認します。合成テストアカウントとその共有リストだけを削除し、利用者のデータには触れません。

障害時はHostingを前の検証済みバージョンに戻します（今回は初回公開のため、必要ならHostingを停止）。Rulesだけを#93へ戻すと共有リストは全拒否になりますが、保存済みデータは消えません。自動で権限を緩めたりデータを削除したりせず、直したルールをEmulatorで検証してから再反映します。
