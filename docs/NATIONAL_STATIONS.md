# 全国のレンタカー・カーシェアを地図で探す

Issue #83。2026-10-01に取得した、日本国内のOpenStreetMap登録情報2,927件を表示します。従来の4地域45件から対象を広げました。**全国を探せますが、すべての店舗が登録されているわけではありません。** 営業・料金・空き状況は公式で確認します。

## まず試す3つの操作

1. `http://127.0.0.1:5173/#/cars` → 上の「浜松町」を押す → ピン → 詳細 → 車候補に保存。「行きたい」の車候補にも反映されます。
2. 「全国」→ 数字の丸を押して拡大。地図を移動し「移動したエリアで検索」でその範囲を検索できます。数字はまとめた登録件数です。一覧は50件ずつ追加表示します。「札幌」「福岡」「那覇」などでも検索できます。
3. 現在地ボタン → 説明を読む → 「現在地を取得」。許可すると約2km以内の掲載拠点を近い順に表示します。なければ「周辺に店舗がない」と断定せず、地図移動や公式検索へ進めます。

地名検索は、主要地域のショートカットと、データに含まれる名称・住所の文字検索です。すべての住所や駅名を位置に変換する検索は未実装です。見つからない場合は現在地や地図移動をご利用ください。絞り込みが残っている場合は「車の事業者フィルター」で条件をリセットできます。

## 浜松町について

浜松町駅の公開座標（35.6554, 139.7571）から直線約2km以内は、この取得時点で3件です。駅のすぐ近くには登録が少なく、地域ショートカットは少し広い範囲を表示します。実際の店舗数とは異なります。未登録の店舗を増やすには、事業者から利用できる情報を得るなど、情報源の追加が必要です。架空のピンや他地域のピンで穴埋めはしていません。

## どんな仕組みか

開発時にOSMの拠点データを1回取得 → アプリに同梱 → アプリ内で地域・種別・事業者を絞り込む → ピンや一覧を表示、という流れです。

地図の背景は、従来どおり国土地理院のベクトルタイルを見ている範囲だけ取得します。拠点検索のたびに外部の検索サーバーへ問い合わせません。広い範囲ではピンを数字にまとめ、端末への負荷を抑えます。全国表示では既存の低縮尺データをさらに縮小し、海岸線も描きます。データがない区画（404）は通信エラーと分けて案内します。最大拡大でも重なる拠点は一覧から選べます。

| 項目 | 今回の範囲 |
| --- | --- |
| 拠点 | OSMの `amenity=car_rental` 2,299件 / `car_sharing` 628件。名称・位置・種別は登録情報 |
| 取得元 | Overpass APIで日本の行政区域内を1回取得。更新担当者用、アプリ利用者の検索には接続しない |
| 元データの基準時刻 | 2026-10-01 13:58:19 UTC（運営による現地確認日ではない） |
| 保存 | 従来のOSM IDを維持。将来の更新で消えたIDも、保存記録を残して情報が確認できない旨を表示 |
| 現在地 | 明示操作による1回取得。端末内で2km検索。非表示・再起動・10分経過で消去 |
| 外部送信 | GPS座標自体はアプリから送信しない。地図の区画番号・IPアドレス等は背景地図配信元へ届く |
| 未対応 | リアルタイム空車、営業確認、閉店の確定、全事業者の網羅、自動更新、全国の住所変換、予約 |

## 費用と今後の人間の作業

今回の追加有料API・サーバー契約はありません。APIキー準備も不要です。「見つける」のOpenAI検索や残り回数には触れません。通信環境の費用は別です。公開後の配信・データ更新・利用規模まで永久無料と保証するものではありません。

今回の操作確認に、追加契約や素材準備は不要です。人間にお願いしたいのは、実機で現在地と周辺の表示を確認することです。今後本公開する場合は、拠点情報の充実に使える情報源・条件（#8）、更新担当と頻度・訂正対応（#21）、背景地図の本公開時の規模・代替配信（#22）を決めます。

## 更新する開発者向けの手順

現在は自動更新しません。必要な時に担当者が取得し、差分をレビューしてアプリを更新します。公共サーバーへ全国取得を繰り返したり、エンドユーザーの検索の裏側で呼び出したりしないでください。

1. [Overpassの公開サービス方針](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html)を確認。次のクエリを一度だけ送信し、結果をローカルJSONへ保存します。混雑・失敗時は連続再試行を避けます。

   ```overpass
   [out:json][timeout:90][maxsize:134217728];
   area["ISO3166-1"="JP"]["admin_level"="2"]->.japan;
   nwr["amenity"~"^(car_rental|car_sharing)$"](area.japan);
   out center;
   ```

2. `node scripts/import-stations.mjs /path/to/downloaded.json YYYY-MM-DD` で検証して取り込みます。部分応答・エラー・重複ID・不正座標・想定外の件数・前回比20%超の減少は停止します。停止時は元のファイルを残して理由を調べます。取り込みスクリプト自身に外部通信はありません。連絡先など表示に不要なタグを除き、出典・基準日時・取得日を残します。
3. `git diff` で件数・消えたID・名称・位置・出典を確認。基準日時と取得日を区別し、両方記録します。表示テストや期待件数も新データに合わせて確認し、ファイルの減少を「閉店」と解釈しません。
4. `node --test scripts/import-stations.test.mjs` → `npm run build` → `PLAYWRIGHT_PORT=5197 npm run test:preview -- tests/national-stations.spec.ts tests/real-cars.spec.ts tests/map-pilot.spec.ts tests/location-search.spec.ts` を実行します。実機確認用は `npm run ios:sync` 後にXcodeで実行します。
