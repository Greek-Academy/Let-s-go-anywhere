# Brave Search + Gemini のローカル試用

Issue [#131](https://github.com/Greek-Academy/Let-s-go-anywhere/issues/131)。PR #130 のGemini検索を土台にした、Macの開発画面用の追加方式です。

## 変更後の動作

Brave SearchのLLM Context APIで出典付きの情報を取得し、Gemini 3.5 Flash-Liteの1回の生成で最大30候補に整理します。Google Routesで所要時間を確認し、時間範囲外を除いて趣味を配分し、最大10パネルを表示します。既存のカード、趣味ラベル、詳細、出典リンク、行きたいへの保存を維持しています。

この方式ではGeminiのGoogle Searchツールを呼びません。Googleの関連検索バーは生成されず、ホームにも詳細にも表示されません。所要時間のGoogle Maps表記は残ります。従来の `research:gemini` 方式ではGoogle検索の出典表示を維持します。

自由記述は入力文、条件検索は選択した条件、イベントは趣味と日付を使います。非ドライブの駅周辺検索にも対応します。根拠不足・経路取得不可を推測で埋めず、10件や待ち時間を保証するものではありません。

## 起動方法

Node.js 24.20.0 / npm 11.19.0。この変更を含むチェックアウトを使用します。

1. `.env.brave.local` に `BRAVE_SEARCH_API_KEY=...`、`.env.gemini.local` に `GEMINI_API_KEY=...` を保存します。ファイルはGit管理外です。既存の `.env.routes.local` をそのまま使います。
2. 検索サーバーを起動します。

   ```sh
   npm run research:brave -- --port 4212 --data-dir .local-research/brave
   ```

3. 別ターミナルでアプリを起動します。

   ```sh
   DRIVEPLUS_SEARCH_BACKEND_PORT=4212 npm run dev -- --host 127.0.0.1 --port 5211 --strictPort
   ```

4. http://127.0.0.1:5211/#/discover を開き、現在地を許可するか駅を選び、「この出発地からドライブ先を探す」を押します。趣味に合わせたカードと時間が出て、Googleの検索候補バーがないことを確認します。

`--demo` を付けると外部通信のない架空サンプルになります。キー変更は検索サーバーの再起動で反映します。4212番のサーバーは1つだけ起動してください。

## 通信・保存・費用

- Braveには検索条件と出発地の駅名／現在地に近い駅・地域名を送ります。GPS座標やキーをURLへ埋めません。キーはサーバーから認証ヘッダーで送ります。
- Geminiには既存と同じ約100m単位の出発位置／駅、検索条件、Braveが返したページの抜粋を送ります。出典IDはサーバー側でURLに対応付け、モデルが作ったURLは採用しません。候補の説明は短い日本語で生成し、長い原文の転載を求めません。
- Routesには出発地と候補の名前・地域を送り、経路や時間の計算結果は端末に永続保存しません。
- Braveの検索応答・原文・検索語・座標はサーバーに保存しません。結果一覧はメモリ内だけで保持し、使用量台帳にはAPI呼び出し数・生成トークン数・状態・時間を記録します。ユーザーが「行きたい」に保存したAIのカードは、既存どおり端末に保存されます。生のBrave応答をキャッシュ／データベース化する機能はありません。
- 通常はBrave検索3回、趣味が多いと最大4回を並列実行し、Gemini生成1回とRoutes行列1回を使います。利用回数の総上限は追加しません。自動再試行・別サービスへの自動切替は行いません。
- Brave Searchの公開単価は1,000リクエストあたり$5、月$5分の無料クレジットです。3回ならBrave分は無料枠適用前で$0.015。GeminiとRoutesは別途の利用量です。台帳のBrave回数は試行数で、請求額は各社管理画面で確認します。モデルの料金を未確認のままゼロとは表示しません。[Brave公式料金](https://brave.com/search/api/)

## 確認結果

2026-11-03、新宿駅を検証用の出発地として実APIを使用しました。個人の現在地を取得した実験ではありません。

| 条件               | 全体時間 | 初期候補 | 表示 | 時間取得 |
| ------------------ | -------- | -------- | ---- | -------- |
| 自然               | 11.397秒 | 30       | 10   | 全10件   |
| 自然・グルメ・温泉 | 12.323秒 | 30       | 10   | 全10件   |

各検索はBrave3回・Gemini1回・Routes1回。2回目は自然4、グルメ2、温泉4枚で、すべての選択趣味が表示されました。Google検索の関連候補HTMLはありません。30秒以内で返った実例ですが、現在地・条件・応答速度で結果と時間は変わります。その後、候補を具体的な施設へ寄せ、趣味の配分を明記する指示を補足しています。最終版を5211番の実画面から検索した確認では、サーバー10.903秒・操作から表示まで11.283秒、自然4・グルメ3・温泉3枚、全10件の所要時間が表示されました。ホームと詳細の関連検索バーは0件、スマートフォン幅で横はみ出しもありません。

サーバー69件、公開検索13件、ブラウザ33件が成功し、型チェック・ビルド・整形・配信物検査も成功しました。通信モックでは、出典IDの偽造、キー不足、429、検索結果なし、並列リクエストの終了待ち、趣味配分、日付付きイベント、旧Google検索の必須出典表示を検証します。ブラウザはPC・スマートフォン幅のChromiumとスマートフォン幅のWebKitで、10枚表示・詳細・保存・検索エラー・バー非表示を確認します。実機iPhone・公開環境への適用はこのローカル試用に含みません。

既存CIで発生していたMiniflare応答の二重読み取りも、失敗時だけ診断文を作り、本文が読めない場合も本来の検証結果を隠さない形に修正しました。公開検索の仕様は変更していません。
