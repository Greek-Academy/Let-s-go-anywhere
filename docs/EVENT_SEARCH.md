# おすすめとイベントを分けて探す（Issue #112）

「見つける」を **おすすめ／イベント** の2つに整理しました。「今週末」はイベントの日付選択、「スポット」はおすすめに統合します。駅・現在地周辺の指定方法は #104・#110 と同じです。

## 試す3操作

1. 「探す地域」で駅周辺または現在地周辺を選び、「イベント」→「今日」「今週末」「日付を選ぶ」を選択します。おすすめで「カフェ」や「自然」を選んでいても、イベントの条件には入りません。
2. 「Webでイベントを探す」を押します。ログイン・参加コードは従来どおり。候補の開催期間・検索日に開催予定の日・時間・会場・出典を確認し、ハート→行きたい→詳細を試します。
3. 「おすすめ」に戻ると入力と結果が残ります。タブ・日付変更、保存、詳細表示では追加検索しません。結果取得後に日付を変えると「前回の検索結果」と表示します。

今日・週末は日本時間です。日曜の「今週末」はその日だけ、平日は次の土日が対象です。日付指定は今日から365日先までの1日。画面を開いたまま日付が変わったときも条件は更新し、自動では検索しません。

## 何をAIへ送る？

```text
おすすめ：選んだ駅ID／概略位置 ＋ ジャンル・追加の希望
イベント：選んだ駅ID／概略位置 ＋ 指定日（1日または土日）
    ↓ 明示的な検索ボタン
Cloudflare検索サーバー：ログイン／入力／共通の累計5回上限を確認
    ↓ 各社1リクエスト、Web検索は各社最大2回、自動再試行なし
OpenAI・Claude：Web検索からイベント情報をJSONで返す
    ↓ 出典URL・形式・日付を検査し、両社で同じ開催回の候補を統合
パネル → 出典・詳細 → 端末に保存／本人の操作で共同リストへ共有
```

キーはサーバーに置いた既存のものを使います。アプリには埋め込みません。イベントでは趣味・おすすめの文章・学習内容は送信しません。現在地の概略化・10分の有効期限・座標非保存は #110 を維持します。

## 開催情報はどこまで確認している？

AIには、主催者・会場の公式ページ、公式観光のイベント情報を優先させます。開催年・開催期間・会場・指定日に実施される根拠が分からないもの、去年の情報、中止・延期、休催日が疑わしいものは除く指示です。長期展示でも、期間が重なるだけで休館日に開催と推測しないよう指示します。

サーバーでは実在する日付か、指定日と重なるか、`occursOn` が期間内か、状態が `scheduled` か、出典URLが検索応答に含まれているかを機械的に検査します。条件に合わない候補は除外し、件数を埋めるための追加検索はしません。0件なら0件として表示します。

**元ページの内容と開催事実を人間が検証したわけではありません。** AIによる抽出ミス、中止・変更の見落とし、位置の誤りまでは機械検査だけで保証できません。「開催予定（AI整理・未確認）」と表示し、訪問前に出典で確認してもらいます。「今日開催中」「安全に行ける」とは判定しません。営業時間・費用・空き・交通条件・写真取得も今回追加しません。

## 保存・費用・以前のデータ

- おすすめとイベントで **1アカウント累計5回を共有**。以前の回数をリセットせず、送信後の失敗も含みます。前回結果を開く操作は無料です。
- 両タブの結果は起動中にメモリ保持。再読み込み後は端末の保存候補と、サーバーの最後の成功結果（全種類を合わせて1件、7日間）を開けます。過去の開催期間の結果は終了表示し、現時点の開催を保証しません。
- イベント保存には期間・対象開催日・会場・時間を追加します。同名・同会場でも別開催回は別候補です。共有時は既存の未確認ステータスに開催期間を含め、学習情報等は送りません。
- 旧「今週末」の設定はイベント＋週末、旧「スポット」はおすすめへ読み替えます。保存済み候補・おすすめの文章・ジャンルは維持します。
- 新しいイベント保存後に古いアプリへ戻すと、旧版の保存形式検査で保護表示になる場合があります。データを削除せず、この変更を含む版で開いてください。
- 契約・追加キーの準備は不要。自動テストは無料の架空応答です。実検索では従来どおり各社API料金が発生し、総額3,000円の費用確認を継続します。
