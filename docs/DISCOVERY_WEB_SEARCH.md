# 「見つける」でWebの候補を探す

Issue [#73](https://github.com/Greek-Academy/Let-s-go-anywhere/issues/73)。検索の土台は #71 / PR #72 です。

既存の「見つける」の地域・検索欄から、検索結果のカード、出典、詳細、「行きたい」まで操作できます。今回は **Macの開発画面・京都市・最大3件** です。写真は取得せず、既存カードの写真枠に「写真は未取得です」と表示します。

## 起動と3つの操作

このプロジェクトで、ターミナルを2つ使います。

```bash
# 1つ目：検索サーバー。既に4181番で起動している場合は重ねて起動しません。
npm run research
```

```bash
# 2つ目：いつものアプリ
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

Macで **http://127.0.0.1:5173/#/discover** を開きます。初回設定が出た場合は設定またはスキップして進みます。今まで `localhost:5173` を使っていた場合はそちらも利用できますが、保存場所は `127.0.0.1` と別なので、同じURLを使い続けてください。

1. **探す：** 「探す地域」を「京都府」にし、「自然とカフェ」などを入力して「Webで候補を探す」を押します。「おすすめ」か「スポット」を選び、興味の絞り込みは「すべて」にします。京都府を選びますが、今回の検索対象は **京都市内だけ** です。
2. **確かめる：** カードの出典を押し、移動先を確認して元ページを開けます。候補の詳細では紹介、希望との関係、検索日時、営業状況・料金・駐車場などの未確認項目を確認します。検索日時は施設へ確認した日ではありません。
3. **残す：** ハートで保存 → 下の「行きたい」→「Webで見つけた候補」から詳細を開きます。同じURLで再読み込みしても保存候補は残ります。未保存の検索結果は再読み込みで消えます。

新規検索はボタンを押したときだけです。入力変更・タブ切り替え・戻る・保存・再読み込みで自動検索しません。入力だけ変えたときは、前回の結果であることを表示します。エラーや0件をサンプルの成功に置き換えません。

## 費用・データへの影響

- **#71と同じ累計3回の実検索上限**です。2026-09-28の接続実装完了時点では1回使用済み、残り2回。別画面の4181番から使った回数も共有します。新たに3回使えるわけではありません。
- 送信後の失敗・タイムアウトも回数に含む場合があります。上限の記録は `.local-research/usage.json` に残し、削除して戻しません。開発の検証は偽の応答だけで行いました。
- APIキーは `.env.research.local` をMacの検索サーバーだけが読みます。アプリに組み込まず、保存候補にも含めません。
- APIへ送るのは「京都市」と今回の希望です。プロフィール、学習回答、不安、相談メモは送りません。検索欄には個人情報を入力しないでください。
- 候補はブラウザ内の既存保存領域に、名前・紹介・出典・検索日時・未確認状態を追加して保存します。保存しても運営確認済みの掲載情報には変わりません。端末間同期はありません。
- 保存データに問題がある場合は既存の上書き保護を維持します。過去の保存形式には空のWeb候補一覧を補い、プロフィールなどを保持します。

新しい保存項目に対応していない旧版へ戻すと、保存の保護表示になる場合があります。その場合は保存データを消さず、今回の変更を含む版で開き直してください。

請求の確認は [#71の検証手順](SPOT_SEARCH_PILOT.md) を参照してください。追加のサーバー・DB契約はなく、累計3,000円の予算を引き継ぎます。

## 費用なしで画面だけ試す

検索サーバーを起動したターミナルのCtrl+Cで停止し、同じプロジェクトで `npm run research:demo` に切り替えます。アプリのURLは5173番のままです。

検索すると「架空の検索サンプル」が出ます。APIキーを読み込まず、有料APIへ接続しません。候補名・紹介は架空で、出典もサイト入口の表示例です。実検索へ戻す場合はサンプルサーバーを停止して `npm run research` を起動します。回数記録は保持されます。

## 処理のつながり

```text
見つける：探す地域 ＋ したいこと
  → 検索ボタン（京都市・入力・対象カテゴリを確認）
  → MacのVite開発サーバー /api/spot-search/*
  → Macの検索サーバー :4181（キー・共通の回数上限を管理）
  → OpenAI Web検索（kyoto.travel限定、検索最大1回）
  → 出典・形式を検査したJSON
  → アプリ側でも検査 → カード → 詳細／出典
  → 本人が保存した候補だけブラウザへ保存 → 行きたい
```

検索サーバーのJSONから、画面に必要な項目だけを取り出します。出典URLを基準にIDを作り、名前の表記や追跡用URLパラメーターが変わっても同じ候補が増殖しないようにします。通常のサンプル掲載データとは別に扱います。

主な実装場所：

| 場所 | 役割 |
| --- | --- |
| `build/searchBridge.ts` | 開発画面からローカル検索サーバーへつなぐ。許可した2経路、localhost、同一Originだけを受け付ける |
| `tools/spot-research/` | #71の検索指示、出典照合、APIキー、回数制限 |
| `src/state/WebSearchState.tsx` | 明示検索、実行中・失敗・回数上限、検索結果と保存操作 |
| `src/domain/webSearch.ts` | JSON・保存データの形式と出典を検査し、候補IDを作る |
| `src/components/WebSpotCard.tsx` / `WebSearchResults.tsx` | 既存カードの見た目を使った結果・未確認・出典表示 |
| `src/screens/WebSpotDetail.tsx` / `Saved.tsx` | 詳細と保存一覧。再読み込み後も保存候補を開く |

## 今回まだできないこと

- **iPhoneアプリ・静的プレビューからの新規検索**：検索サーバーを未接続のため、理由を表示します。Xcodeの▶を押すだけで実検索できる段階ではありません。公開API、認証、利用上限の運用は #13・#14・#31 の後続です。MacのAPIキーをアプリに入れる方法は採りません。
- 他地域、SNSの自動検索、写真取得、経路・距離検索、営業時間や空き状況の保証。
- 予算・帰宅時刻・避けたい運転場面への適合判定。条件は保存できますが、Web候補に合うかは未確認です。
- 検索結果の共有・DB同期・運営確認済みデータへの自動掲載。施設確認と写真の利用条件確認は引き続き保留です。
