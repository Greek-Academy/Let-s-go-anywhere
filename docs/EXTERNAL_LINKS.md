# 外部リンクの共通処理（#24の先行部分）

本人が保存したURLを確認して開く操作と、将来の確認済みデータ向けのリンク判定を追加しました。新しい外部API、認証、課金サービスはありません。外部ページの取得・解析・生存確認は行いません。

## いま有効な操作

「行きたい」の保存リンク →「元の投稿を確認」で移動先ホストとURLを表示し、「元のページを開く」で別タブ／対応アプリを開きます。本人が保存したURLは「内容未確認」のままで、おすすめの掲載データや確認済み施設には変わりません。

新規ウィンドウが使えない場合は「開けない・アプリがないとき」から同じタブで開けます。戻ると保存や検索条件はlocalStorageから復元されます。保存領域が使えない場合は同じタブへの案内を出さず、元のタブを残すように案内します。

HTTPや不正なURLが保存されていても削除はせず、外部へ開く操作だけを停止します。HTTPを勝手にHTTPSへ置き換えません。既存の保存時のURL正規化と、外部へ開くときの厳しい検証は役割を分けています。

## 掲載先リンクの準備

`Outing`・`Station`・`School`・`ArrivalGuide`に任意の`links: ListingLinks`を用意しました。共通モーダルへの入力は`ExternalRequest`です。

| 入力 | 条件と結果 |
| --- | --- |
| `personal` | 本人が保存した公開HTTPS URLのみ。内容・正当性の確認済み表示は付けない |
| `listing` + `catalogSource: sample` | URL・座標・確認状態が入っていても外部へのリンクを作らない |
| `listing` + `catalogSource: approved` | 停止状態でなく、対象リンクに確認済み根拠・確認日・期限がある場合に判定する |
| 未確認・未来・期限切れ・取り下げ・利用停止 | 対応する案内理由を表示し、そのリンクは開けない |

現在の`ContentCatalog`とビルドは**sampleのみ**を受け付けます。`approved`の分岐は将来の検証済みアダプター向けの準備で、今回のカタログに承認済み実データを接続していません。各画面はカタログのsourceをそのまま渡し、保存データやURLパラメーターで承認状態を切り替えません。型は任意の外部JSONの入力バリデーターではありません。

- `official` / `app` / `sns`：利用可能状態と`Evidence<{ url, host }>`。hostは運営が確認した正規化後のホストに完全一致させる。部分一致や任意サブドメイン一致はしない。
- `map`：利用可能状態と`Evidence<MapPlace>`。緯度経度、または確認済み住所のいずれか。手描きの地図上のx/y、架空の拠点名、ユーザーの入力住所から補完しない。
- 本文や許諾記録などの私的なメモはリンク情報に含めない。既存の確認期限判定と同じく日本時間の期限当日まで有効。
- 公式Webとアプリ用URLは先行版ではパスのみ。クエリ・フラグメント付きは、勝手に削って別URLを開かず利用を止める。必要な公式パラメーターの運用は後続で決める。
- HTTPSのUniversal / App Linkのみを扱い、独自スキームや`intent:`は開かない。アプリ用リンクは有効な公式Webの代替がある場合だけ出す。アプリの導入状態を推測しない。
- 地図・関連SNSリンクが停止していても、別途確認済みで有効な公式Webがある場合はそちらを案内する。

## URL・外部への受け渡し

`src/domain/externalLinks.ts`に検証・期限判定・地図URL構築をまとめました。公開HTTPS、ホスト形式、認証情報、IP／端末内ホスト、通常以外のポート、制御文字、エンコード後の2,048文字制限などを確認します。入力URLの形式が正しくても、内容・現在の接続可否・遷移先の正当性を保証するものではありません。

地図には `https://www.google.com/maps/search/?api=1&query=...` の形式で、確認済みの地点だけを渡します。URLSearchParamsで住所をエンコードし、プロフィールの出発地・ユーザーID・学習回答・相談メモは入力に受け取りません。地図への所在地表示であり、車入口や走りやすさ、所要時間を判定する機能ではありません。APIキーは不要なMaps URLsを使う構成です。[Google公式仕様](https://developers.google.com/maps/documentation/urls/get-started)

リンクは通常のa要素で、`target=_blank`・`rel="noopener noreferrer"`・`referrerPolicy="no-referrer"`を付けます。外部側に元タブのopenerとReferrerを渡さず、自動通信・自動転送・予約完了の記録はしません。外部操作直前にも期限を再確認し、モーダルのフォーカス移動にリンクを含めています。[a要素の仕様](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/a)

本人の保存URLにもともと含まれるクエリやフラグメントは、そのURLの意味を変えないため保持します。アプリ内の個人情報を付け足さないという制約とは別です。開いた先でのリダイレクトやトラッキング、ログイン、外部サービスの動作は制御できません。リンク切れ・404はこのアプリが検知したと表示せず、利用者向けの代替案内を用意しています。

[操作手順・画面例](reviews/external-links/README.md)を参照してください。

検証：PC・スマホ幅のChromiumでブラウザの別タブと同じタブへの遷移を動かします。外部ページのHTTP応答はPlaywrightで差し替え、テストでは実サービスへ通信しません。承認済み公式・地図・アプリ用レコードは架空のテスト入力だけを使って純粋関数で判定を検証します。実在施設やネイティブアプリへの実遷移を確認したものではありません。

人間の後続：#19・#21・#23の公式URL・実座標／住所・掲載状態・許諾、URLのアプリ対応と案内文の確認、#12の期限運用。施設選定・写真許諾の保留は継続します。

開発の後続：承認済みデータアダプターの検証・接続、実データでのリンク有効化、URL変更／停止の配信、監視と運用、必要な公式パラメーターの承認方式、実機Safari/iOS・Androidでのアプリ有無／OSから戻る動作の検証。全体の完了条件は未達なので#24は閉じません。
