# 別のスマホと「行きたい」を共有するための準備

現在は端末内の操作デモです。実際に2人で共有するには、**2台が読み書きする共通の保存先**と、**誰の操作か確認するログイン**を用意します。今回はその役割にFirebaseを使う設計です。

2026-10-04：ユーザーがSparkプロジェクト作成・Webアプリ登録・メール/パスワード認証・Firestore作成を完了しました（#91完了）。CLIログイン後、#93の本人用リスト保存ルールを反映し、実クラウドで保存とアクセス拒否を確認しました。次は自分のメールでの登録・確認・保存です。[接続検証の3つの操作](FIREBASE_CONNECTION_PILOT.md) を参照してください。以下はプロジェクト作成時の手順として残します。

## 完了した準備：検証用プロジェクトを1つ作る

1. 管理に使いたいGoogleアカウントで [Firebase Console](https://console.firebase.google.com/) にログインします。
2. 「プロジェクトを作成」から、例として `Driveplus共有検証` の名前を入れます。既存の仕事用・本番用プロジェクトとは分けてください。
3. プロジェクトIDが表示されたら控えます。表示名とIDは別です。ここで出るプロジェクトIDを後で接続先の確認に使います。
4. Google Analyticsの利用選択が出たら、今回の検証では無効で進めます。
5. 作成後、料金プランが **Spark（無料）** であることを確認します。今回はBlazeへのアップグレードや請求先アカウントの連携は行いません。
6. 「プロジェクトを作りました」と、プロジェクトIDを教えてください。パスワードやサービスアカウント秘密鍵は不要です。

**今の人間TODOはここまでで大丈夫です。** アプリ登録・ログイン方式・保存先は、接続の実装に合わせて次の段階で案内します。OpenAI APIキーはこの機能に使いません。現在の`.env.research.local`の変更も不要です。

Firebaseの作成・Webアプリ登録の流れは [公式セットアップ](https://firebase.google.com/docs/web/setup) に基づきます。Sparkは支払い情報なしで開始できる無料枠のあるプランです。機能・上限は [公式料金プラン](https://firebase.google.com/docs/projects/billing/firebase-pricing-plans) で確認できます。利用量を測る前に、継続運用や全国公開も無料とは判断しません。

## 接続時に進める順序

| 順序 | 人間が行うこと | 開発側で行うこと |
| --- | --- | --- |
| 1 | 上記のプロジェクト作成、Spark確認 | 接続先を確認、別IssueでFirebase SDK・設定の読み込みを実装 |
| 2 | 管理画面で必要な設定を確認 | Webアプリ登録手順、メール・パスワード認証と確認メールの案内を用意 |
| 3 | DBの保存地域を確認（作成後の変更が難しい項目） | Firestoreの文書設計、権限ルール、Emulatorで権限・競合・期限の検証 |
| 4 | 確認相手1人と、別々のテスト用ログインを用意 | HTTPSの招待ページとアプリを接続。保存・反応・退出の往復を確認 |
| 5 | 体験と共有の説明を確認 | 実送信回数・読み書き回数・費用の記録、Issueへ結果を掲載 |

先にFirestoreを作る場合は、Standard edition・本番環境モードで読み書きを拒否した状態から開始します。テストモードによる全公開でアプリの動作を通すことはしません。アプリ向けの読み書きルールは開発側でテストしてから適用します。[Firestore公式の開始手順](https://firebase.google.com/docs/firestore/quickstart)。

認証はまずメール・パスワード＋確認メールを候補にします。パスワードをこのアプリ独自の保存先へ記録する仕組みは作りません。[Firebase公式の認証手順](https://firebase.google.com/docs/auth/web/password-auth)。

## 実共有の完了条件

Aさんが候補を追加 → Bさんのスマホで取得 → Bさんが「気になる」 → Aさんで取得、を別々のアカウントで実際に確認します。招待取り消し、未承認アクセスの拒否、退出後のアクセス拒否、保存失敗時の表示、再起動後も見られることも確認します。

設定値を入れただけ、同じ端末で役を切り替えただけでは、実共有の完了にはしません。親Issue #40で残作業を管理します。
