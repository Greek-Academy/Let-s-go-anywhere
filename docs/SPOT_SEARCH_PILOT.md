# 地域と「したいこと」から候補を探す：最小検証

Issue [#71](https://github.com/Greek-Academy/Let-s-go-anywhere/issues/71)（親 #35）。更新：2026-09-28。

**実検索1回目が成功しました。** 京都市・自然とカフェの希望から3件を取得し、約15秒、利用量からの参考費用は約$0.014でした。[結果・出典との照合・改善点](reviews/spot-search-pilot/LIVE_RESULTS.md)を参照してください。実検索は1/3回、本人の候補評価と実請求確認は残っています。既存アプリの画面は維持し、検証後に検索処理を接続する方針です。

目指す体験は、普段Chrome・SNS・ChatGPTを行き来して探している候補を、地域と希望の入力からカードで比較できることです。今回は京都市、最大3件で取得項目・正確さ・費用を確認します。初期テーマは「自然を楽しんで、カフェにも寄りたい」。検索テーマは80文字まで変更できます。

## 今回使う情報源

- OpenAI Responses APIのWeb検索を利用し、京都市公式観光サイト `kyoto.travel` に絞ります。サイトのすべてのページや最新情報を網羅する保証はありません。
- Google Places・TikTok・XのAPIキーは今回不要です。SNSの検索や写真取得は次の段階です。
- モデルは `gpt-5-mini`、推論は `low`、検索コンテキストは `low`、出力上限6,000トークン（推論分を含む）。検索ツール呼び出し上限1回・APIリクエスト上限3回で検証します。
- 候補の名称・地域・短い紹介・条件との関係・根拠URL・検索日時を表示します。写真・営業時間・料金・駐車場は未確認とします。
- モデルが返したURLを、APIの検索元一覧または引用メタデータと照合します。これは本文の正しさの認定ではありません。人が元ページと候補を見比べます。
- 公式サイトへの直接スクレイピングや画像の複製は行いません。公開配信に進む前の掲載・利用条件の確認は #7・#17 で継続します。

## 最初にキーなしで試す

プロジェクトのターミナルで実行します（Node.js / npmはCONTRIBUTING.md参照）。

```bash
npm run research:demo
```

Macのブラウザで **http://127.0.0.1:4181/** を開きます。

1. 京都市・希望を確認して「サンプルのカードを確認する」を押す。
2. 3枚のカードと出典リンクの位置を確認する。施設はすべて架空で、リンクはサイト入口の例です。
3. 「検証結果をファイルに保存」でサンプルのJSONを保存する。

サンプルは外部通信・API費用なしです。実検索失敗時にサンプルへ置き換える動作はありません。

## APIキーを準備する

必要なのは **OpenAI APIキー1つ** です。ChatGPTアプリの月額契約とは別に、API側の利用設定が必要です。キーや請求画面の個人情報をチャット・Issue・PRへ貼らないでください。

1. [OpenAI Platform](https://platform.openai.com/)にログインし、この検証用のプロジェクトを用意します。
2. [API Keys](https://platform.openai.com/api-keys)でキーを作成します。制限付きキーならResponses APIへのリクエストを許可します。組織の設定によって画面や権限は異なります。
3. 必要な課金設定はPlatformのBillingで確認します。前払い入金を求められた場合、その入金も累計3,000円の予算に含めます。最低入金額・税・為替は画面で確認し、予算を超える設定や自動追加購入をしないでください。
4. このプロジェクト直下の **`.env.research.local`** をエディタで開きます。今回、空の入力欄を用意しています。ない場合は `tools/spot-research/key.env.example` をこの名前でコピーします。
5. 次の右側にキーを入れて保存します。引用符は省略できます。

```dotenv
OPENAI_API_KEY=ここに自分のAPIキー
```

`VITE_`は付けません。このファイルはGit対象外で、ローカルのNodeサーバーだけが読み込みます。画面に入力する欄は設けていません。

準備できたら「ファイルに保存した」とだけ伝えてもらえれば、実検索の検証を続けられます。

## 実検索を試す

サンプルサーバーをターミナルのCtrl+Cで停止し、次を実行します。

```bash
npm run research
```

同じ **http://127.0.0.1:4181/** を開き直します。「実検索の検証」と表示されることを確認し、「候補を探す（APIを1回利用）」を押します。起動・画面表示・再読み込みだけではAPIを使いません。キーの変更後はサーバーを再起動してください。

検索には最大2分程度かかることがあります。入力した地域・希望と固定の検索指示をOpenAIへ送ります。通常アプリの保存、プロフィール、学習、不安、相談メモは送りません。個人情報を検索欄に入力しないでください。

試すのはMacのブラウザです。現在のiPhoneアプリには接続していません。通常の5173番、掲載情報入力ツールの4180番とは別です。今回の検索結果を通常アプリへ自動掲載・同期する処理はありません。

## 費用と停止の仕組み

2026-09-27に確認した公式料金では、モデル入力100万トークンあたり$0.25、キャッシュ入力$0.025、出力$2。Web検索は1,000回あたり$10と検索内容のトークン料金です。画面ではAPIから得た利用量をもとにUSDの参考額を計算します。

例えば入力2,400・出力900・検索1回なら、計算上は約$0.0124です。これは計算例で、実測値や実請求の保証ではありません。実請求額は[Usage](https://platform.openai.com/usage)で確認します。料金変更・検索の課金内訳・税・為替・前払い入金は参考計算と分けます。

- 実検索は最大3回。1回につきAPIリクエスト1回、検索ツール最大1回。自動再試行・定期検索なし。
- APIへ送る前に回数を記録します。通信失敗・回答不完全・タイムアウト・プロセス停止も回数に含めます。
- `.local-research/usage.json` に回数・日時・完了状態・利用量・所要時間だけを記録します。入力文・候補本文・キーは記録しません。
- 再起動しても回数は維持します。記録の破損・ロック中は実行しません。サーバー側の回数制限であり、アカウント全体の請求上限ではありません。
- 利用量を取得できない回は「費用未確定」です。0円にはしません。
- 利用記録を削除して回数を戻す操作は提供しません。3回で結果を評価し、追加実行は改めて範囲を決めます。
- プロセスが記録中に異常終了して `usage.lock` が残る場合は、全検証プロセスの停止と `usage.json` の試行数を開発側が確認してからロックだけを扱います。利用記録は削除しません。

## 人が確認する項目

「検索で見つかった」と「情報が正しい」を区別します。各回で次を記録します。

| 項目 | 記録すること |
| --- | --- |
| 条件 | 地域・入力した希望 |
| 取得 | 候補件数、欠けた項目、除外件数 |
| 出典との一致 | 施設名・所在地・紹介文が元ページと合っているか |
| 地域・希望との一致 | 京都市内か、したいことに合うか |
| 体験 | 行きたいと思える候補があったか、結果までの時間 |
| 費用 | API利用量の参考額、Usage画面の請求額、未確定な回 |
| 次の判断 | 同条件で続ける／情報源を変える／取得項目を調整する |

「検証結果をファイルに保存」で取得結果を手元へ保存できます。Git対象外の名前で保存し、公開Issueには長い原文・キー・私的な検索内容を貼りません。正確さや掲載許可が確認できていない候補は公開承認と扱いません。

## 開発側の検証

```bash
npm run test:research
npm run test:research:ui
```

単体テストは偽のAPI応答を使い、回数制限・再起動・費用不明・タイムアウト・出典のない回答・キー非公開・リクエスト元の制限を確認します。ブラウザテストはサンプルモードでPC・スマホ幅のChromium/WebKitを確認します。CIは実APIキーを使わず、課金しません。

検証画面は専用サーバーの許可した3ファイルだけを配信し、127.0.0.1だけで待ち受けます。API呼び出しには同じOriginと一時トークンを要求します。通常アプリのビルドやiOS資材には検証サーバー・キー・利用記録を含めません。
