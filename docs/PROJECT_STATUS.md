確認日：2026-09-17。最新の着手状況は[全体管理Issue #1](https://github.com/Greek-Academy/Let-s-go-anywhere/issues/1)に反映します。すべてのIssueやコードを読む必要はありません。

**現在は、一人で操作の流れを試せるモックです。本物の施設情報を探し、講習会社へ相談が届くサービスには、まだつながっていません。**

予算上限は初期費用と運用費を合わせた累計3,000円です。当面は追加サービス費用0円で進めます。施設選定・施設情報と写真の利用条件の確認は、ユーザーの指示により保留しています。

## なぜIssueがたくさん残るのか

Issueには、画面、実データ、会社との合意、公開後の運用まで含む大きな作業があります。例えば「相談」は送信画面まで試せますが会社には届かないので、Issue全体は閉じていません。

開発の変更履歴・自動テスト・保存データの保護など、画面が変わらない準備も進めました。今後はその必要性と、実運用にどう近づくかを毎回説明します。

開発基盤の#4はPR #47の反映と検証記録に基づき、完了として閉じました。#17は入力、#18は終了・更新、#19は利用者向け表示を担当し、目的が異なるためまとめて閉じません。一部実装とIssue全体の完了を分けます。

## 次の候補はこの3つ

以下は提案で、今回の整理では新機能を実装していません。すべて追加サービス費用0円で先行できる範囲です。

### ① 出発エリアと表示候補の関係を分かりやすくする — #19

**今やる理由：** 出発エリアを「京都」にしても同じ6件のサンプルが並ぶことを確認しました。出発エリアは保存・車探し・条件判定に使われますが、ホームの候補選びには反映されていません。

- 変更：出発地と探す対象地域を区別し、対応するサンプルの表示、対象がない場合の説明、本人による対象地域の変更をつなぐ。
- あなたの確認：対応地域で見る → 未対応地域に変える → 自分で探す地域を広げる。
- 完了の基準：対象がない地域でも近場のおすすめに見せかけず、理由と次の操作が分かる。趣味・保存・開催状態を維持し、出発地を勝手に変更しない。移動時間・運転しやすさは推測しない。
- 人の準備：実際にどの地域の情報を揃えるかは#2・#7で後から決める。今回はサンプルで確認可能。

### ② 入力した候補をアプリ全体で試せるようにする — #17・#19

**今やる理由：** 現在の入力ツールはカードの見本までです。情報を集めた後に、入力とアプリがつながらないという手戻りを減らします。

- 変更：架空の入力データを開発用のアプリ全体プレビューへ渡し、一覧・詳細・保存まで確認する。私的な確認メモは除外する。
- あなたの確認：架空のイベント名を変える → 一覧と詳細で確認 → 保存してもう一度開く。
- 完了の基準：入力内容が同じ候補として反映され、不正入力で元データを壊さない。入力不足・期限切れ・写真なしも説明する。「入力が揃った」と「公開承認済み」を区別し、サンプル表示と普段の保存領域の分離を維持する。
- 人の準備：本物の公開、施設・写真の確認、サーバー保存は後続。今回の動作確認は架空データのみ。

### ③ 文字を大きくしたスマホでも主要操作を確認する — #32

**今やる理由：** 文字拡大の設定はあります。小さい画面・大きな文字でも保存や相談のボタンまでたどり着けるかを追加確認します。特定の不具合が既に見つかったという意味ではありません。

- 変更：文字拡大・幅320px・入力・下から開く画面・同意画面の組み合わせを確認し、見つかった問題を修正する。
- あなたの確認：設定で文字を大きくする → 候補を保存 → 相談内容の確認画面まで進み、戻る。
- 完了の基準：文字・ボタンが読める、必要な場所へスクロールできる、閉じる・戻る・入力が使える。問題がなければ不要な画面変更を追加せず、検証結果を記録する。
- 人の準備：自動テストは開発側で行う。実際のスマホのキーボード・読み上げは人の確認として別に残す。

共同リスト・休日プラン・SNS自動収集・通知・大きな開発道具の更新は後で扱います。下見カードは追加4案の中での優先度を維持し、施設・写真の確認待ちとします。

## あなたが確認する3つの操作

開発サーバー起動中の http://127.0.0.1:5173/ で試せます。`localhost`・`127.0.0.1`・ポート番号が違うURLでは保存場所が分かれるので、同じURLを使います。

1. **行きたいまで：** 見つける → ハートで保存 → 行きたいから開く。「使いたい／迷った／期待と違う」を記録する。
2. **準備まで：** 候補の詳細 → 運転の準備 → チェックを回答またはスキップ → 結果・学習を見る。「運転してよいという判定」と誤解しないか確認する。
3. **相談まで：** 講習 → 会社の詳細 → 相談メモ → 共有内容の確認。「何を相手に伝えるか」が分かるか確認する。現在はデモで、会社へは届かない。

回答例：「保存は分かった。共有内容の画面で、どこまで相手に見えるか迷った」。コードやテストログの確認は開発側が担当します。相談の個人内容や許諾メモは公開Issueに貼らず、架空の例や操作箇所で伝えてください。
