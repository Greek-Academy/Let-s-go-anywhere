# 静的配信物のバックアップと復元

Issue #33の先行部分です。配信するHTML・JS・CSS・画像と`release.json`を一式保存し、欠損や変更を検出して別フォルダへ復元します。Node標準機能だけを使い、追加サービス費用は0円です。予算は初期費用と運用費を合わせた累計3,000円以内とし、有料の保存先・監視サービス・自動課金は追加しません。

## 対象と限界

- 対象は、コミット済みの変更のないチェックアウトから生成したサンプル検証版です。既存の配信物検査にも合格する必要があります。
- バックアップはアプリのファイルです。本人のlocalStorage、相談メモ、入力ツールの作業データ、DB、秘密情報は取り込みません。端末内データの取り出しは[保存データの復旧案内](STORAGE_RECOVERY.md)で扱います。
- SHA-256は保存後の欠損・変更を検出します。署名ではなく、ファイルと記録の両方を書き換えられる相手への真正性保証ではありません。信頼するCI実行・コミットSHAと照合し、管理するフォルダに保管してください。
- 外部への配信・切り替え・通知・費用の自動取得は行いません。復元先で操作確認してから、管理者が配信先の手順で切り替えます。
- 復元はデータ形式を巻き戻しません。同じ配信元・同じ保存形式での検証です。別オリジンでは保存データは引き継がれず、保存形式が異なる旧版への互換性も保証しません。

## バックアップを作る

作業中の`dist`やリポジトリ全体ではなく、CIが検証した配信物を対象にします。CI Artifactは14日で期限切れになるので、戻す可能性のある版は別途保管します。保管期間・管理者・保存場所は運営側で決めます。ローカルディスク内のコピーだけでは端末故障への対策にはなりません。

ローカルで試す場合は、変更のないコミット済みブランチで次を実行します。

```bash
npm run build
npm run verify:preview -- --for-upload
mkdir -p ../driveplus-releases
npm run release:backup -- create dist ../driveplus-releases/preview-v1
npm run release:backup -- verify ../driveplus-releases/preview-v1
```

CI Artifactをダウンロードした場合は、`dist`の代わりに展開したフォルダを指定できます。成功時にコミットSHA、ビルド時刻、ファイル数・合計サイズをJSONで表示します。CIのPR検証は一時マージSHAの場合があります。変更元ブランチのSHAだけで判断せず、CI実行と`release.json`を照合してください。

```text
preview-v1/
  backup.json   形式・作成時刻・ファイルごとのサイズとSHA-256
  payload/      検査した配信ファイル一式
```

保存先には**存在しないフォルダ**を指定します。親フォルダは先に用意してください。コピー中は元ファイルを変更しないでください。コピー後にも照合し、不一致・コピー失敗時はこのコマンドが作成した出力を削除して失敗を返します。処理が強制終了した場合は不完全なフォルダが残る可能性があります。`verify`に通らないものを配信せず、元のCI Artifactから別名で作り直してください。

## 問題が起きた版から戻す

```bash
npm run release:backup -- verify ../driveplus-releases/preview-v1
npm run release:backup -- restore ../driveplus-releases/preview-v1 ../driveplus-restored-v1
npm run preview -- --outDir ../driveplus-restored-v1 --host 127.0.0.1 --port 4191 --strictPort
```

最後のコマンドで http://127.0.0.1:4191/ を開きます。既存のサーバー・フォルダは上書きしません。別ポートの確認URLでは普段のlocalStorageは共有されないため、初回画面になる場合があります。

1. 信頼するCI実行のSHA・ビルド時刻と、復元した`release.json`が一致することを確認する。
2. 初回設定、5つのタブ、保存・再読み込み、詳細、画像を確認する。
3. 公開済みの場合は管理者が復元した**配信フォルダだけ**を再配信する。`backup.json`やリポジトリ全体は配信しない。
4. 実配信URLのファイル・主要操作・キャッシュ・HTTPヘッダーを確認する。CI実行、SHA、復旧時刻、結果をIssueへ記録する。

再配信の共通手順は[静的検証版のガイド](STATIC_PREVIEW.md)を参照してください。配信側のキャッシュや公開環境での切り替えは今回のローカル復旧試験には含めていません。

## 停止する条件

| 条件 | 動作 |
| --- | --- |
| 元の配信物が未コミット変更あり・未対応の公開区分・不完全 | バックアップを作成しない |
| ファイル欠損・追加・サイズやSHA-256の不一致 | 復元先を作成しない |
| 記録の不正形式・未対応バージョン・不正パス | 復元しない。記録上のパスを開かない |
| リンク、特殊ファイル、個人データの既定の書き出し名、入れ子のバックアップ | 取り込まない |
| 出力先が既に存在・入出力先が重なる | 元データ・既存フォルダを上書きしない |
| 記録が1MiB超、配信物が1,000ファイル超・1ファイル25MiB超・合計128MiB超 | 処理を停止する |

正常終了は終了コード0、失敗は1です。失敗を無視して配信を続けないでください。ファイルの内容全般を対象とする秘密情報スキャナーではありません。バックアップの名前・場所を変えて配信フォルダに混ぜないでください。`release-backups/`・`release-restores/`はGitと配信検査から除外していますが、保管はリポジトリ外を推奨します。

## 自動検証

```bash
npm run test:release-backup
# 変更のないコミット済みチェックアウトでbuildした後に実行
CI=true PLAYWRIGHT_PORT=5190 npm run test:preview -- tests/release-recovery.spec.ts
```

Nodeの9件は異常系と往復復元を確認します。ブラウザ試験はChromium PC・モバイル相当・WebKitモバイル相当で、本物のビルドとCLIを使います。隔離した一時フォルダ・ブラウザ・ローカルサーバーで保存→503の配信失敗を模擬→復元した配信物へ切り替え→保存内容と5タブ・詳細・画像を確認します。通常のブラウザや開発サーバーのデータは変更しません。未コミット変更ありのビルドでは復旧試験だけをスキップします。CIでは変更のないビルドで必ず実行します。

## 残作業

- 人間：公開範囲と管理アカウント、保管先・保管期間、復旧担当と応答目安、停止・再開の権限を決定する。施設・写真の確認は引き続き保留。
- 開発：採用した配信サービスでの復旧・HTTPヘッダー・キャッシュ検証、障害や情報更新遅延の監視、費用の累計と無料枠の使用量の監視。
- 本番DB等の導入時：認可を伴うバックアップ・削除済みデータの扱い・復元・送信状態の整合性を検証する。

Issue #33全体は開いたままです。この実装で本番公開の承認や監視体制の完成を意味しません。
