# ラーメンタイプ診断

「見つける」の上部にある「ラーメンタイプ診断」から、写真100枚への回答と結果確認ができます。元の完成済み100問版を、Drive+の画面・保存方法に組み込んだものです。APIキー・サーバー・追加の従量課金は使いません。

## まず試す操作

1. ホーム → ラーメンタイプ診断 → 診断をはじめる。写真を見て3択から選び、「次の写真へ」を押します。写真を押すと拡大画面を開けます。「2倍に拡大」で大きくし、上下左右へスクロールして細部を確認できます。
2. 数枚回答し、右上のホームボタンで戻ります。再読込／アプリ再起動後にカードを開くと「続きから回答する」が表示されます。「前の写真」や「回答を見直す」で変更できます。
3. 100枚を終えると結果が表示されます。4軸と追加の特徴、回答写真、16タイプ、仕組み・出典を確認します。回答を変え、「結果を更新して戻る」を押すと再計算されます。

全て🔺の場合は「今回はタイプを保留」となります。好みスコアは○＝100・△＝50・×＝0を集計した数値で、診断が当たる確率ではありません。

写真が読み込めない間は回答できません。エラー時は「写真を再読み込み」、または「読込不可として進む」を選べます。読込不可は🔺と区別して保存し、採点から除外します。既に選んだ回答を読み込みエラーだけで勝手に変更することはありません。

## 起動と画面のつながり

```bash
npm ci
npm run dev
```

通常は `http://localhost:5173/#/discover` を開きます。作業ブランチの確認用サーバーは別ポートを使う場合があります。

```text
見つける /discover
  → 説明・再開 /ramen
    → 写真1〜100 /ramen/question/1 … /100
      → 結果 /ramen/result
        → 回答一覧 /ramen/review → 回答変更 → 結果
        → 仕組み・写真の出典 /ramen/about
どの診断画面からも右上のホームアイコンで戻れます。
```

既存のReact・HashRouter・スマホフレーム・下部ナビゲーションを使います。診断本体は開いた時に読み込み、CSSは`ramen-`で始まるクラスに限定しています。

## 保存と書き出し

- 回答と現在の写真番号を既存の`AppState.ramen`に保存します。ブラウザは既存のlocalStorage、iOSアプリは既存のCapacitor Preferencesです。既存データに診断項目がなくても、他の保存項目を維持したまま追加します。
- 結果は保存された回答から元のロジックで再計算します。回答と古い結果が食い違うことを避けるため、結果のコピーは別に永続化しません。
- 診断データは端末内だけです。Firebase共同リスト・AI検索・他人の端末へ自動送信しません。別ブラウザ／別端末との同期や、元の別サイトからの回答移行は今回の対象外です。
- 既存の「端末データを初期化」で回答も消えます。ストレージへの保存に失敗した場合は、既存の復旧案内に加えて診断の進捗欄にも未保存を表示します。
- 「結果をコピー」はクリップボードを使い、利用できなければ選択・コピー用のテキスト欄を表示します。
- Webの「テキストで保存」は`.txt`をダウンロードします。iOSの「共有・テキスト保存」は標準の共有シートを開き、メモ等へ渡せます。表示される保存先は端末の設定・インストール済みアプリによります。

| 組み込み先 | 内容 |

| `src/ramen/provenance.json` | 元ファイル・写真のSHA-256、データ内容の比較用ハッシュ |
| `public/images/ramen/` | 使用する100枚のJPEGを同じバイト列で同梱 |

写真は100枚・58店、合計8,138,201 bytes（約7.76 MiB）です。回答時には店名・価格・口コミ評価を出しません。店ごとに均等な重みを付ける処理、最低枚数・店舗数、10ポイントの境界、1店ずつ除く安定性確認、回答の偏りによる保留、好みの文章生成は元の処理です。

写真と出典は依頼された参照元から引き継いでいます。出典表示は利用許諾そのものを意味しません。外部公開時の利用条件・許諾確認は、元プロジェクトの記録と併せて別途確認してください。この変更で外部サイトへの新規公開は行っていません。

## 開発側の検証

```bash
npm run format:check
npm run build
CI=true PLAYWRIGHT_PORT=5192 npm run test:preview -- tests/ramen-scoring.spec.ts tests/ramen-flows.spec.ts
```

- 元の採点との比較：全100回答を含む41通りと、未完了6通り。タイプだけでなく全スコア・判定・内訳・文章を比較します。完了分は書き出しテキストも比較します。
- 元データとの比較：100問の順序、プロフィール内容、100写真のハッシュ、16タイプ、出典の存在。
- 操作：ホーム、3択、前後、拡大、回答変更、離脱・再開、100問完走、全🔺保留、エラー・再読込・読込不可、結果・出典・書き出し。
- 保存：旧データへの項目追加、他の保存内容の維持、不正な回答／問題番号／異なるデータ版の検出。WebテストでPreferences／Shareとの接続境界も検証します。

iPhoneシミュレーター用の`testRamenDiagnosisResume`は、実際のWKWebView・Preferencesで写真回答→アプリ終了→再起動→途中再開・回答維持を確認します。テストはデータのない専用シミュレーターで実行してください。

```bash
npm run ios:sync
xcodebuild -project ios/App/App.xcodeproj -scheme App \
  -destination 'platform=iOS Simulator,id=専用シミュレーターのUUID' \
  -only-testing:AppUITests/DrivePlusUITests/testRamenDiagnosisResume \
  CODE_SIGNING_ALLOWED=NO test
```

実行結果と画面は[確認記録](reviews/ramen-diagnosis/README.md)にまとめます。実機iPhoneでの長時間の回答・共有先での保存は、人間の最終確認として残します。
