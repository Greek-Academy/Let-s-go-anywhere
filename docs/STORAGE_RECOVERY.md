# ブラウザ内の保存データの検証・復旧

Issue #31の先行部分。認証・API・共有権限の実装とは別に、現行モックのlocalStorage入力と、読み込み失敗時の上書きを扱います。

## 読み込みの境界

`src/state/model.ts`に画面用の型と初期値、`src/state/storage.ts`に入出力の検証を分離しました。キーは従来の `driveplus.mock.v1` のままです。

- JSONを型の宣言だけで信用せず、既知の項目だけから新しいオブジェクトを組み立てます。文字列／真偽値／数値／配列／記録の形式と選択値を検証し、文字列を真偽値などへ自動変換しません。
- 有効なv1の保存は維持します。既知の古い保存で欠けている項目は初期値で補います。単に開く／再読み込みするだけでは元のJSONを保存し直しません。
- ある領域に不正値があれば、その領域は初期値にし、ほかの読み取れる領域を表示します。不正な配列を一部だけ成功した履歴に作り替えることはしません。元データは自動で変更しません。
- 未知の項目や将来の形式、`__proto__`／`constructor`／`prototype`は受け入れず、保存を保護します。端末内の`contentSource`などを掲載データの承認には使いません。
- 相談履歴の日時、デモ状態、共有項目とスナップショットの一致を確認します。同意日時が欠けた履歴に同意を補ったり、未選択項目を追加したりしません。
- URLの文字列は個人の未確認保存として扱います。古い不正URLも文字列として残せますが、実際に開く処理には既存のHTTPS・ホスト検証が必要です。HTMLはReactの通常のテキスト表示で扱い、自動取得・実行・おすすめへの公開は行いません。

上限はJSON解析前に2,097,152 UTF-16コード単位、コレクションは各1,000件、文字列は各20,000コード単位、IDは160文字です。超えた内容を切り詰めて上書きせず、元の保存を残してタブ内の利用へ切り替えます。書き込みにも同じ検証を適用します。通常の入力で上限を超えた場合も、新しい入力はタブ内に残り、最後に保存できたデータを維持します。

## 保存を止める場合

| 状況 | 挙動 |
| --- | --- |
| 不正なJSON、型、未知の形式、読み込み上限超過 | 自動保存を停止。読める領域だけ表示し、元データを維持 |
| 保存領域の読み取りが拒否される | 元データがあるか判断できないため、書き込まずタブ内だけで利用 |
| 容量不足・書き込み例外・書き込み形式の上限 | 最後の保存を維持。連続で再試行せず、設定の「保存をもう一度試す」で本人が再試行 |
| 書き込み直前に、読み込み時／前回保存時と異なる値が見つかる | 別タブ等の内容を上書きしないよう停止。再読み込みで最新を読む |

別タブの検出は書き込み直前の比較です。同時書き込みを原子的に制御する仕組みや同期・マージではなく、競合を完全には防げません。DB導入時の権限・バージョン管理・排他処理は別途必要です。

## 設定からの対処

画面上部の保存状態から設定へ移動できます。通知はアプリ本文と別の領域に置き、下部タブや入力ボタンの上に重ねません。モーダルを開いた間は通知のボタンも背景として操作対象から外します。

- **元データのダウンロード:** 本人がボタンを押したときだけ、現在そのブラウザに保存されている文字列をJSONファイルとして取り出します。タブ内だけの未保存変更を含めず、サーバー送信・修復・自動インポートはしません。
- **再読み込み:** タブ内だけの変更は失われることを表示します。必要な入力を手元へ控えてから、ブラウザ側で操作します。
- **初期化:** 既存の「モックの保存データを削除」から確認します。キャンセルなら何も削除せず、確定時だけ元データとタブ内状態を削除します。削除に失敗したときは成功扱いでウェルカムへ移動しません。

ダウンロードしたファイルは相談メモ等を含む本人用のデータです。公開Issue・リポジトリへ添付するためのログではありません。エラー処理に入力本文・元JSONを出力する処理は追加していません。既定のバックアップファイル名はGit対象外とし、配信物検査でも拒否しますが、任意名のファイルや任意の秘密情報をすべて検出する機能ではありません。

## 今回の限界と後続

- localStorageは本人が変更できるデータです。形式が正しいことを、本人確認・共有同意・実際の受付の証拠には使えません。
- 本番の認可、会社間の分離、CSRF／SSRF、サーバー取得のリダイレクト制限、送信の冪等性、レート制限、秘密情報検査全般は未実装です。#13・#15・#20・#27・#29の接続時に検証します。
- 自動修復・バックアップのインポート・DBバックアップ／復元は今回の対象ではありません。保存されていたデータを取り出せることと、復元済みであることを区別します。
- 閲覧用の掲載情報入力ツールのJSON形式とは別です。本人用バックアップを掲載情報として取り込む機能はありません。
- 読み取り拒否中は、元データのダウンロードも失敗し得ます。画面にその旨を示し、元データの有無や削除成功を推測しません。
