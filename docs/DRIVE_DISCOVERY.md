## 探し方の違い

| 探し方 | 使う条件 | 他の入力の扱い |
| --- | --- | --- |
| ① 出発地と趣味から探す | 現在地または駅、初期設定の趣味、片道2〜5時間 | 自由入力・気分条件は使わない |
| ② 自由に書く | 出発地、入力した希望、片道2〜5時間 | 気分条件・初期設定の趣味は使わない |
| ② 気分から選ぶ | 出発地、時間、したいこと、道、時間帯、ペース | 自由入力・初期設定の趣味は使わない |
| イベント | 出発地、趣味、日付、片道2〜5時間 | 自由入力・気分条件は使わない |

趣味はおすすめ・イベントの両方に使います。未選択ならジャンルを限定しません。複数選んだ場合は全趣味の一致を必須にせず、候補全体で選択内容を反映するよう依頼します。出発地・趣味・入力方法を変更しただけでは追加検索しません。検索ボタンを押したときに現在の条件を反映します。②の切り替えでも入力内容は保持します。

気分の選択肢には自然・海・高原・湖・夜景・夕日・星空・季節の風景・グルメ・カフェ・温泉・写真・街並み・アート・動物・道の駅・景色のいい道を用意しました。活動は6つまで、道には高速道路・一般道・県越え、ペースには滞在・寄り道・走る時間を選べます。予算入力はありません。

アプリを新しく起動・再読み込みしてホームを開くと、現在地と趣味で一度自動検索します。OS・ブラウザの位置情報許可は必要です。取得・検索の失敗時は自動再試行しません。詳細から戻る、タブを切り替える、趣味を編集するだけでは追加検索しません。バックグラウンド復帰や位置の期限切れも自動再検索しません。再取得・再検索はボタンから行えます。検索サーバー未接続の静的サンプル版では自動取得を行いません。

検索結果は4種類ごとに画面内で維持します。提案元の絞り込みと待ち時間・参考料金の欄を削除し、出典・説明・イベント日付は詳細に集約しました。Googleの所要時間には出典表記、イラストには「イメージ」を残します。保存した候補は「行きたい」に残ります。

## 候補と所要時間が出るまで

1. 端末の位置を約100m単位（小数3桁）へ丸めます。位置の許可がない場合は駅の座標を利用します。
2. サーバーがOpenAI・Anthropicへそれぞれ1回問い合わせます。各社最大10候補、Web検索は各社最大2回です。従来の徒歩圏2kmには限定しません。
3. 出典・形式・イベント日付を検査して重複をまとめます。AIには所要時間を生成させません。紹介文・推薦理由に数値の時間表現が混ざった場合、その文を除きます。時間欄はRoutesの計算結果のみです。
4. Routesキーがある場合、Google Routes APIのCompute Route Matrixに1回だけ問い合わせます。出発地1件×候補最大20件です。通常の運転時間を計算し、現在の渋滞は加味しません。一般道希望時は高速回避を指定します。高速利用や県越え自体を確定するものではありません。
5. 取得した時間が希望範囲外なら除外し、最大10件を表示します。未取得は「所要時間は未確認」と表示します。10件未満でも架空の情報で埋めません。失敗時に自動再検索はしません。

Googleへ渡す目的地は候補名・地域（イベントは会場名）です。駐車場入口を確認した経路ではありません。片道時間に滞在・休憩・復路は含みません。「安全」「初心者向け」といった実技判断はしません。

## あなたにお願いする設定：Routes APIの専用キー

写真用のPlaces APIキーを変更せず、同じ検証プロジェクトに**新しいキー**を作ります。

1. [Routes APIを開く](https://console.cloud.google.com/apis/library/routes.googleapis.com?project=driveplus-photos-pilot)。画面上部が `driveplus-photos-pilot` であることを確認します。
2. 「有効にする」を押します。「管理」と表示されていれば有効化済みです。
3. [認証情報を開く](https://console.cloud.google.com/apis/credentials?project=driveplus-photos-pilot) →「認証情報を作成」→「APIキー」。
4. 作ったキーの編集画面で名前を `Driveplus Routes` にします。「APIの制限」で **Routes APIだけ** を選択して保存します。写真用のキーはPlaces API (New)のままです。
5. 今回はMacのサーバーから送信するため、「ウェブサイト」「iOSアプリ」の制限は選びません。固定の送信元IPが決まっていないローカル検証中は「アプリケーションの制限：なし」で扱い、キーは端末内だけに保管します。公開サーバーへ使う前に送信元制限を見直します。
6. 次のファイルを開き、`=` の右へキーを貼り付けて保存してください。キー本体をチャット・GitHubへ貼る必要はありません。

```text
/Users/seyamayoshihiko/Desktop/letsgoanywhere/.env.routes.local

GOOGLE_ROUTES_API_KEY=ここに作成したキー
```

保存できたら「保存しました」と伝えてください。こちらで準備状況を確認します。設定反映に時間がかかる場合があります。キーはアプリに配布せず、サーバーだけで読みます。

### 費用

Googleの課金設定が必要です。無料クレジットや無料枠を含めた実際の請求条件はGoogle Cloud側で確認します。MatrixはHTTPリクエスト数だけでなく、出発地×目的地の要素数で使用量が計上されます。今回1検索で最大20要素です。

2026-10-21の利用者の明示指示により、アプリが使う比較検索の回数上限を撤廃しました。ローカル累計6回・公開コードのアカウント累計5回を撤廃し、過去の利用台帳は維持します。公開サービスへの反映には別途デプロイが必要です。新しい検索には各社のAPI料金が発生します。認証・同時実行防止・1検索あたりのWeb検索最大2回/社・応答待ち期限は維持します。

## 保存・送信の範囲

- 趣味・気分条件・選択中の探し方・保存候補は既存のlocalStorage / iOS Preferencesを利用します。
- 保存済みの駅・同行者・興味・行きたい・学習は維持します。駅はプロフィールで引き続き編集できます。
- GPSは取得から10分間だけメモリに保持。一時的なタブ・アプリ切り替えでは検索と表示済みの時間を維持し、復帰だけで再検索しません。復帰時にも期限を確認し、期限切れ・ページ離脱・再読み込み・アプリ終了・保存データ削除・ログアウトで破棄します。座標を端末・共有リスト・検索履歴ファイル・D1に保存しません。「車を探す」の現在地処理は今回の変更対象外です。
- Googleの時間・距離は現在の表示にだけ使用し、10分で未確認に戻します。保存・共有・サーバーの結果保管から除外します。カードにGoogle Maps表記、詳細画面に利用規約・プライバシーポリシーへのリンクを表示します。
- 公開側の検索結果・条件の既存7日保管と累計回数台帳は維持します。おすすめ・イベント検索では選択した趣味を検索条件として送信します。学習や共有相手の情報は送信しません。
- 旧ラーメン確認版の既知の保存形式だけ読み飛ばします。元プロジェクトは変更していません。
